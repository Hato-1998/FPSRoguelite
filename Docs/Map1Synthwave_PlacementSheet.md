## 1. `FPSRFlowFieldBoundsVolume` × **정확히 1개**

Place Actors 패널에서 `FPSRFlowFieldBoundsVolume` 검색 → 레벨에 드롭.

| 넣을 곳 | 항목 | 값 |
|---|---|---|
| Details > **Transform** | Location | `0, 2250, 850` |
| Details > **Transform** | Rotation | **전부 0** (돌리면 AABB가 커져 셀 예산이 깨진다) |
| Details > **Transform** | Scale | `1, 1, 1` |
| 컴포넌트 트리에서 **BoundsBox** 선택 → Details > **Shape** | Box Extent | `22600, 24900, 750` |
| 액터 루트 선택 → Details > **FPSR \| Flow Field** | **Cell Size Override** | **250** |
| 같은 섹션 | MapId · Unified Extent · Climbable Step Height Override · Probe Apex Above Origin Override | **전부 기본값 그대로** (미설정 / false / 0 / 0) |

**결과 월드 박스**: X `-22600..22600` · Y `-22650..27150` · Z `100..1600`

판정 근거:
- 셀 **181 × 200 = 36,200** / 상한 40,000 ✅, 축당 ≤ 256 ✅
  (검증기 식 = `ceil(크기 ÷ 셀)`, [FPSRBlockoutValidator.cpp:120](../Source/FPSRogueliteEditor/Private/Blockout/FPSRBlockoutValidator.cpp#L120))
- 가드레일 #6: 박스 중심의 첫 지면 Z=199 ≤ `Min.Z 100 + 150` ✅
- Probe Apex 기본 2000 → 격자원점 200 + 2000 = 2200 > 고가지면 800 ✅ 그대로 두면 된다
- **셀 200cm는 쓸 수 없다** — 225 × 248 = 55,800으로 상한을 넘는다. 런타임은 죽지 않고 셀을 자동으로 키우지만,
  "레벨 검증"이 Error로 잡는다. 그래서 250을 명시한다.

## 2. `PlayerStart` × 1 — `-864, 2266, 300`

- Rotation은 아레나를 바라보게 자유롭게(격자에는 영향 없음).
- **이 액터가 플로우필드 격자의 Z앵커를 정한다** — [`DetectFloorZ`](../Source/FPSRoguelite/Private/Enemy/FPSRFlowFieldSubsystem.cpp#L44)가
  *첫 PlayerStart 아래로 트레이스*해서 격자원점 Z를 잡는다.
- 그래서 **PlayerStart 아래에 장식물 콜리전을 놓으면 안 된다**(격자 Z가 그리로 끌려가 지면 시드가 전멸한다).
  이 좌표는 아래가 비어 있고 사방 개방도 8/8인 걸 확인한 지점이다.

## 5. 남은 이슈 (배치와 별개)

- **`SM_stairs` 2개는 적이 못 오른다.** 상승 685cm를 수평 1670cm만에 올라가 셀당 102.6cm —
  오를 수 있는 최대(60)의 1.7배다. 셀을 200으로 낮춰도 82cm라 마찬가지이므로 **셀 크기 문제가 아니라 계단이 가파른 것**이다.
  적을 그리로 올리려면 수평 런을 늘려야 하고, 아니면 장식으로 두면 된다(플레이어는 그대로 오른다).
- `Min Player Distance` 0 → 플레이어 코앞에서도 스폰될 수 있다. 템포 보고 올릴 값.
