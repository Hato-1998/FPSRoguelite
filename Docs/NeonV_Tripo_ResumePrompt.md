## 2. 전제 — 적(정적 메시)과 다르다
- **3인칭 몸체 = Blu 스켈레톤(108본) 스켈레탈 메시.** 슬라이드 4클립·벽 4자세·로코모션이 전부 이 스켈레톤 위에 있다(`Docs/Architecture/0002*`, 메모리 blender-locomotion-anim-authoring). Tripo 결과는 새 메시(+선택 자체 리깅)라 **임포트만으로는 못 쓴다.**
- **1P = 총만 표시(ADR 0015)** → 이 몸체는 **협동 팀원 시점(3P)** 과 로비/초상화에서만 보인다. 투자 규모를 여기에 맞춰 판단한다.
- **아트 방향 미결**: 2026-09-03 결정은 레트로 아케이드·복셀이 메인인데 이 시트는 고디테일 애니메. 플레이어 룩(복셀 vs 셀 고디테일 vs 팀원 몸체만 이 룩)은 「아트 방향 ADR 저작」 행의 결정 항목 — **이 트랙이 선점하면 안 된다.** 결정 전엔 §3-1 실측까지만.
- 기존 함정(전부 이 경로에 있다): FBX 미터→cm 100배 축소(`fbx-metre-cm-armature-scale-trap`), OBJ/FBX Y 반전(Troubleshooting D12), 기존 스켈레톤 지정 임포트가 스켈레톤을 덮어씀(`ue-import-overwrites-target-skeleton`), 리그드 GLB 헤드리스 임포트 크래시(`glb-import-crash-use-fbx`), IK 리타게터 무음 실패(`ik-retargeter-op-chain-mapping`), Blender 1cm ≠ UE 1cm(0.8806).

## 3. 통합 경로 후보와 비용(추정 — 1단계 실측 후 숫자로 갱신할 것)
| # | 경로 | 살아남는 것 | 비용·위험 |
|---|---|---|---|
| 1 | **Blu 스켈레톤에 새 메시 스키닝**(Blender: 정렬 → 웨이트 전이 → FBX) | 애니·ABP·1P 파이프라인 전부 | 사람이 Blender 에서 며칠. 비율 차이(시트 = 긴 다리·큰 머리)만큼 웨이트 손질. 권장 후보 |
| 2 | Tripo 자동 리깅 + IK 리타게팅 | 새 스켈레톤 | 리타게터 무음 실패 + 슬라이드 발 접지·벽 자세 재손질. 1 보다 크고 회귀 위험 높음 |
| 3 | 정적 포즈 프록시(로비 전시·초상화·팀원 마커) | 리깅 불필요 | 게임플레이 몸체는 안 바뀜. 아트 결정 전 임시 활용 가능 |
| 4 | **복셀 변환**(사용자 지시 2026-09-06: "저 캐릭터 디자인을 복셀로 바꾸는 것도 포함") — Tripo 메시(또는 시트 기반 손 저작) → `.vox`(FileToVox/MagicaVoxel) → 복셀 메시 | 아트 방향(레트로 아케이드·복셀)과 정합. 적 파이프라인(`gen_voxel_chomper.py` 계약·격자선 머티리얼)을 공유 | ⚠️ 플레이어는 **애니가 필요**하므로 복셀 메시도 결국 Blu 스켈레톤에 **스키닝**해야 한다(경로 1 의 복셀판). 복셀 캐릭터 스키닝은 관절이 딱딱 끊기는 룩이 되는데, 이게 아케이드 룩에선 오히려 정답일 수 있다(마인크래프트식 관절). 격자 크기가 곧 표현 한계 — 162cm 에 6~8cm 격자면 얼굴 디테일(바이저·헤드셋·리본)은 색 면으로만 남는다. 1P 는 총만 보이므로(ADR 0015) 팀원 시점 가독성 기준으로 격자 크기를 정한다 |

### 3-0. 복셀 경로(4)의 구체 절차 초안
1. Tripo GLB → Blender Remesh(Blocks) 또는 FileToVox 로 격자화(격자 6/8/10cm 세 버전 뽑아 팀원 시점 거리 6~10m 에서 가독 비교).
2. 팔레트 규약으로 부위 색 분리(적과 같은 방식: 팔레트 인덱스 = 요소/부위) → `.vox` → 변환기(`vox2chomper.py` 계획, 적 트랙에서 먼저 만든다) 로 OBJ.
3. 스키닝: 복셀 메시를 Blu 리그에 웨이트 전이(경로 1 과 동일 도구). 관절부는 복셀 단위로 갈라지므로 **관절 위치가 격자 경계와 맞게** 격자 원점을 정렬한다.
4. 1P 팔은 ADR 0015 로 숨김이라 무관. 3P 팀원·로비 노출만 검증.

### 3-1. 1단계 실측 절차(다음 세션)
1. Tripo GLB → Blender(`F:\Blender\blender.exe` 5.1) 임포트, `NeonV_locomotion.blend`(블랜더 repo `C:\Users\koras\Desktop\작업\개발작업\블랜더`) 의 Blu 아마추어 옆에 놓는다. **키 184cm(Blender 값)로 맞춘다**(UE 162 ÷ 0.8806).
2. 대조 항목: 어깨폭·팔 길이·다리 길이·머리 크기 비율 차 / 폴리 수 / 텍스처 유무 / 닫힌 메시인지(리본·헤드셋 분리 여부).
3. 보고 형식: 경로 1 예상 공수(시간), 경로 2 예상 공수, 어느 부위가 스키닝 위험인지 — **숫자로**. 결정은 사용자.
