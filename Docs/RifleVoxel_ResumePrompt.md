> 기각된 대안 = 3cm 이상(칸이 클수록 단순해져 §4-2 에 유리하다는 반대 논리는 성립하지만,
> 파츠 구분이 먼저다). 1~2cm(복셀로 안 읽힌다).

🔴 **파츠 분리이므로 모든 파츠가 같은 2.5cm 격자에 정렬돼야 한다.** 파츠마다 격자가 어긋나면
접합부에서 칸이 반칸씩 밀려 보인다.

⚠️ **1인칭 무기는 카메라에서 30~50cm 앞에 있다.** 같은 칸 크기라도 월드 오브젝트보다 훨씬 크게
읽힌다 — 아레나 셀 200cm·적 캡슐 80×180cm 와 **직접 비교하면 안 된다.**
→ **`Docs/SSOT/ArtDirection.md` 에 전역 복셀 격자로 올릴 것**(적·환경도 같은 격자를 써야 한다).
다만 무기는 근접 관찰물이라 **환경이 같은 2.5cm 를 써야 한다는 뜻은 아니다** — 배수 관계
(2.5 / 5 / 10cm)로 잡는 편이 안전하다.

### 2-2. 총구가 향하는 축 — ✅ **결정됨: +X 정면** (사용자, 2026-09-03)
현행 DA 는 `ADSAimRotationOffset = Yaw 90` 인데, 이건 **Synty 팩의 총구가 +Y 라서** 넣은 보정값이다.
**복셀 라이플은 +X 정면으로 저작**하므로 이 값은 **0 으로 되돌려야 한다.**
그대로 두면 ADS 에서 총이 90도 틀어진다 — 그리고 **경고 없이** 틀어진다(§6-2 가 판정 항목).

### 2-3. 색을 텍스처로 넣을 것인가, 머티리얼로 넣을 것인가 — ✅ **결정됨: B안** (사용자, 2026-09-03)
지금 아케이드 룩은 **텍스처가 한 장도 없다** — 바닥·벽·적 전부 절차적 머티리얼이다

#### 🔴 B안이 성립하려면 먼저 확인할 것 (이 문서는 실측하지 않았다)
**Blockbench 가 머티리얼 그룹을 여러 개로 나눠 내보낼 수 있는가?** 여기서 막히면 B안은 설계대로
안 돌아간다. **모델링을 시작하기 전에** 작은 테스트 모델(2색 큐브 2개)로 왕복 검증할 것 —
전체를 만든 뒤에 알면 재저작이다.

확인 결과에 따른 사다리(위에서부터 시도):
1. **OBJ + 머티리얼 그룹** — 되면 그대로 간다. 임포트 선례가 OBJ 다(`import_enemy_proto_meshes.py`).
2. **glTF/GLB** — glTF 는 머티리얼별로 primitive 가 갈리므로 구조적으로 확실하다. 임포트도
   이미 실증돼 있다(`Troubleshooting.md` D1-b — *"같은 GLB 가 크래시 없이 들어옴"*).
   ⚠️ 메모리 `glb-import-crash-use-fbx` 의 크래시는 **무거운 리그드 캐릭터** 사례라 정적 무기엔 해당 없다.
3. **색 구역별로 파일을 나눠 익스포트** — 슬롯이 아니라 **메시를 쪼개는** 방식. 투박해 보이지만
   §2-4 에서 **파츠 분리를 택하면 어차피 이 형태가 된다**(파츠는 각자 자기 메시·자기 머티리얼이다).
   → **§2-3 과 §2-4 는 같이 정하는 게 싸다.**

### 2-4. 한 덩어리인가, 파츠로 쪼갤 것인가 — ✅ **결정됨: 파츠 분리 + C++ 가드 확장** (사용자, 2026-09-03)
파츠 분리(몸통 + 총열 + 조준경 + 탄창)로 간다. 진화·모듈러가 살고, §2-3 의 머티리얼 슬롯 문제도
같이 풀린다(파츠는 각자 자기 메시·자기 머티리얼이다).

**단, §1-2 대로 현재 코드는 정적 무기에 파츠를 안 붙인다.** 검토한 세 갈래 중 사용자가 **가드 확장**을

- ❌ 복셀 무기를 스켈레탈로 승격(Blender 로 최소 스켈레톤 추가) — 코드 무수정이지만 무기마다 Blender 단계가 붙는다
- ✅ **C++ 가드 확장** — 파츠 부모를 `WeaponMesh` → `ActiveWeaponMesh` 로. Blender 불필요
- ❌ 파츠 포기

→ **작업 내용은 §3-2 에 있다.** 코어 무기 코드 변경이므로 **플랜 게이트를 거친다**(§3-2 참조).

> 테스트 목적은 "**한 파츠 안에서** 발광부를 따로 뽑을 수 있는가"로 좁혀진다.

그리고 확정된 칸 크기(2.5cm)를 **`Docs/SSOT/ArtDirection.md` 에 전역 복셀 격자로 올린다**(§2-1).

### 3-1. 규격서 → 사용자 저작 (Blockbench, 프로젝트 밖) — **§3-2 와 병렬**
**규격은 이미 확정돼 있다. 아래를 그대로 넘기면 된다.**

| 항목 | 값 |
|---|---|
| 복셀 1칸 | **2.5cm** — 모든 파츠가 같은 격자에 정렬 |

사용자가 익스포트한 파일을 `Saved/RifleVoxel/` 에 둔다(선례 = `Saved/EnemyProto/`).

### 3-2. C++ 가드 확장 — 정적 무기도 파츠를 받게 (§2-4) 🔒 **플랜 게이트 대상**
사용자가 Blockbench 로 모델링하는 동안 **병렬로** 진행한다. 복셀 에셋이 없어도 구현·빌드가 된다.

**변경 지점 3곳** (실측 2026-09-03, `Source/FPSRoguelite/Private/Hero/FPSRCharacter.cpp`):
| 줄 | 현재 | 바꿀 것 |
|---|---|---|
| `:2529` | `if (!Weapon \|\| !WeaponMesh \|\| ActiveWeaponMesh != WeaponMesh)` | 스켈레탈 강제를 풀고 `!ActiveWeaponMesh` 로 |
| `:2573` | `if (!WeaponMesh) { return; }` | `ActiveWeaponMesh` 기준으로 |
| `:2608` | `PartComp->AttachToComponent(WeaponMesh, ...)` | 부모를 `ActiveWeaponMesh` 로 |

**이미 확인된 것 (다시 조사하지 말 것)**
- 🟢 **순서 위험 없음** — `ActiveWeaponMesh` 는 `:2348` 에서 채워지고 `RefreshWeaponPartComponents` 는
  `:2448` 에서 불린다. 가드는 항상 최신값을 읽는다. 무기 없는 경로도 `:2272`(null) → `:2302` 로 정합.
- 🟢 **파츠는 이미 `UStaticMeshComponent`** (`:2600`) — 부모만 바뀌면 된다. 정적 메시의 소켓은
  `UStaticMesh::Sockets` 로 지원되고 `AttachToComponent(..., SocketName)` 이 그대로 해석한다.
- 🟢 **ADS 조준 해석은 이미 정적 대응** — `:2472-2476` 이 *"파트 우선, 없으면 `ActiveWeaponMesh`"* 로
  이미 짜여 있다. 여기는 손댈 필요 없다.
- 🟢 **복제 영향 없음** — 파츠는 복제되지 않는다. 각 클라이언트가 복제된 무기/프래그먼트 상태
  (`WeaponInventory->GetCurrentInstance()`)에서 **로컬로 재생성**한다. 즉 **코스메틱 로컬 변경**이라
  4인 협동에서 새로 생기는 네트워크 표면이 없다. (그래도 §6 판정은 **리슨 호스트 + 원격 클라 양쪽**에서 —
  메모리 `event-halves-authority-vs-client`.)

**게이트**: 코어 무기 코드 변경이므로 CLAUDE.md 모델 배분을 따른다 —
`Opus 조사·플랜 → Fable 플랜 게이트 → 사용자 승인 → Sonnet 구현 → Opus 검증 → Fable 머지 게이트`.
조사는 위 표로 이미 끝나 있으니, 플랜은 **"스켈레탈 전용을 가정한 다른 지점이 더 없는지 훑는 것"** 이
본론이다(위 4건 외에 `CachedLeftHandComponent`/`CachedRightHandComponent`·렌더 태그 상속 경로).

**검증**: 빌드는 `-DisableUnity -ForceUnity` 로(메모리 `nonunity-build-is-67-seconds`,
`Troubleshooting.md` G13 — 그냥 `Succeeded` 는 유니티 충돌을 검증하지 못한다).
회귀 확인 = **나이프**(기존 정적 무기)가 파츠 0개인 채로 여전히 정상인지, **Synty 라이플**(스켈레탈)의
파츠가 그대로 붙는지 둘 다.

### 3-4. 소켓 (에디터 켜짐 또는 헤드리스)
🔴 **소켓을 전부 몸통에 만들면 안 된다.** 현행 라이플 실측(2026-09-03)이 규약을 보여준다 —
몸통 `SK_Wep_Mod_A_Body_01` 의 소켓은 **9개뿐**이고, 그중 **`SOCKET_Aim`·`SOCKET_Muzzle` 은 없다**:

| 몸통에 있는 것 (9) | 어디에 |
|---|---|
| `SOCKET_Mount_{Barrel,Handguard,Stock,Mag,Grip,Trigger,Reddot}_0` | 파츠 마운트 7개 |
| `SOCKET_LeftHand` · `SOCKET_RightHand` | 양손 IK |

**`SOCKET_Muzzle` 은 총열 파트에, `SOCKET_Aim` 은 조준경 파트에 산다.** 이건 우연이 아니라
`Docs/WeaponPack_Integration.md` 가 명시한 규약이다(*"총구 = 파트 소켓"* · *"ADS 조준 = 사이트 파트 소켓"*),
그리고 코드도 그 전제로 짜여 있다 — `FPSRCharacter.cpp:2472-2476` 이 *"파트 우선, 없으면 `ActiveWeaponMesh`"*
로 조준 컴포넌트를 푼다. 총열이나 조준경을 바꾸면 총구·조준선이 **따라 움직여야** 하므로 구조적으로 맞다.

→ 복셀 라이플도 같은 규약을 따른다: **마운트 7개 + 양손 2개는 몸통에**, **총구는 총열 파트에**,
**조준선은 조준경 파트에.**

**축 참고**: Synty 몸통은 총 축이 **본 공간 Z**(양손 소켓 델타 dZ 22.0 로 실증)라서
`ADSAimRotationOffset = Yaw 90` 이 필요했다. 복셀은 **+X 정면**(§2-2)이므로 그 보정을 **0 으로** 되돌린다.

⚠️ 정적 메시의 소켓은 `UStaticMesh::Sockets` 이고 스켈레탈과 API가 다르다.
⚠️ 스켈레탈 쪽 함정(소켓이 메시가 아니라 **스켈레톤**에 산다 — 메모리 `arms-socket-lives-on-skeleton`)은
정적 메시엔 해당 없지만, **바디 쪽 `SOCKET_Weapon` 은 여전히 캐릭터 스켈레톤에 있다.**
⚠️ 파이썬으로 소켓 **읽기**: `sk.num_sockets()` + `get_socket_by_index(i)` + `find_socket_info(name)`.
`sockets` 프로퍼티는 protected 라 `get_editor_property` 로는 못 읽는다(2026-09-03 실측).

### 3-5. 머티리얼 (에디터 켜짐 — 라이브 생성·편집은 안전)
**B안 확정이므로 텍스처를 만들지 않는다.** 슬롯별 절차적 MI 를 물린다 —
레시피는 `MI_Pac_WallEdge`(모서리 발광)·`MI_EnemyProto_AtomCubes`(프레넬 실루엣 림 +
노멀 변화율 하드 엣지)를 그대로 가져다 쓴다. 무기는 각진 면이 많아 **하드 엣지 레시피가 특히 잘 맞는다.**

슬롯 배분 초안(§2-4 파츠 결정과 맞물린다): `Body` · `Barrel` · `Grip` · `Emissive`.
발광 슬롯은 §4-2 대로 **작은 면적에만** — 총열 히트싱크·조준경 도트 정도.

색은 §4-1 대역(**V 25–70 · S 30–60**) 안에서, §4-1 의 🔒 예약색 회피 규칙을 지킨다.
머티리얼 검증은 **`get_statistics` 를 쓰지 말고** `get_material_diagnostics()` +
`export_material_graph()` 로(§5-3).

## §5 함정 — 이 트랙에서 반드시 밟게 되는 것

### 5-1. 🔴 임포트는 **실행 모드를 틀리면 죽는다** (그리고 정답이 있다)
| 실행 모드 | 결과 |
|---|---|
| **라이브 에디터**(MCP/Python) | ❌ **게임 스레드 데드락.** 강제 종료 외 방법 없음 (`Troubleshooting.md` D1-a) |
| **`-run=pythonscript` 커맨드렛** | ❌ 임포트 직후 Slate 없어 어설션 즉사 (D1-b) |
| ✅ **헤드리스 정식 에디터** | ✅ `-nullrhi -unattended -nosplash -ExecCmds="py <script>"` — 실증 2026-08-14 |

⚠️ **`Docs/ArcadePostProcess_ResumePrompt.md` §4-1 은 이 지점에서 틀렸다.** 그 문서는
*"두 실행 컨텍스트 모두에서 죽는다 … 세 번째 우회를 찾지 말 것"* 이라고 적었는데, **세 번째 우회는
이미 존재하고 문서화돼 있었다**(`Troubleshooting.md` D1-b 말미). 그 세션은 그걸 못 찾은 것이다.
→ **텍스처가 필요해도 사용자에게 떠넘기지 말 것.** 헤드리스 정식 에디터로 들어간다.

### 5-2. 커맨드렛/헤드리스는 **종료 코드로 판정하면 안 된다**
`Troubleshooting.md` C4 — 작업은 끝났는데 마지막에 UI 동기화로 죽어 exit 3 이 나오는 경우가 많다.
→ 스크립트가 찍는 **완료 마커**와 **`does_asset_exist`**, 그리고 **`git status`** 로 판정.
`save_asset` 은 기본이 `only_if_is_dirty=True` 라 **로그엔 성공, 디스크는 그대로**가 된다 →
`only_if_is_dirty=False` + git 대조.

### 5-3. 머티리얼 검증에 `get_statistics` 를 쓰지 말 것
그래프를 바꿔도 **같은 숫자를 계속 돌려준다**(생성 시점 값 고정). 2026-09-03 에 `sin`/`cos` 8회 루프를
넣어도 `PS=85` 가 미동도 안 한 것으로 실증했다 — `Troubleshooting.md` **G14**.
→ `get_material_diagnostics()`(`.is_compiled_ok`/`.compile_errors`) + `export_material_graph()`(연결 전량).
배선은 전부 `link()` 헬퍼로 감싸 **실패를 수집**할 것 — `connect_material_expressions` 는 이름을 못 찾으면
**조용히 False** 다(**D10**).

### 5-4. 스케일 — FBX/glTF 는 미터↔cm 에서 100배로 어긋난다
메모리 `fbx-metre-cm-armature-scale-trap`. 임포트 직후 **바운드를 cm 로 찍어 §2-1 에서 정한 전장과
대조**할 것. "들어왔다"는 "맞게 들어왔다"가 아니다.

### 5-5. 스켈레톤을 대상으로 하는 임포트는 하지 말 것
기존 스켈레톤을 지정해 임포트하면 뼈가 안 맞을 때 **그 스켈레톤 에셋을 통째로 갈아엎는다**
(메모리 `ue-import-overwrites-target-skeleton`). **§2-4 가 정적 메시 + C++ 가드 확장으로 확정됐으므로
이 트랙에서는 해당 없다** — 스켈레톤을 아예 안 만든다. 기각된 갈래(스켈레탈 승격)로 되돌아가는 일이
생기면, 그때 임포트는 **사람이 에디터에서** 해야 한다는 것만 기억할 것.

### 5-6. 열린 에디터가 `.uasset` 을 잠근다
임포트/머지 전 **에디터 종료**. 메모리 `ue-editor-file-locks-block-git`.

## §6 판정 기준 (사용자 PIE)

1. **크기가 맞는가** — 화면에서 총이 차지하는 면적이 종전 Synty 라이플과 비슷한가
2. **ADS 에서 조준선이 화면 중앙에 오는가** — §2-2 축 결정과 `ADSAimRotationOffset` 이 맞물렸는지
3. **총구 화염이 총구 끝에서 나는가** — `MuzzleSocket` 위치
4. **양손이 총을 잡고 있는가** — 좌/우손 IK 소켓
5. **적이 여전히 먼저 눈에 들어오는가** — §4-2. 무기가 시선을 뺏으면 실패다
6. **복셀로 읽히는가** — §2-1 칸 크기 판정. "각져 보이긴 하는데 복셀은 아닌" 상태가 제일 흔한 실패

## §7 미결 / 이 트랙 밖

- **나머지 무기 8종** — §2-5 에서 파일럿으로 정하면 여기로 이월된다.
- **적·환경 복셀 격자** — §2-1 에서 정한 칸 크기는 무기만의 것이 아니다. `ArtDirection.md` 에
  전역 규격으로 올려야 적/환경 저작이 같은 언어를 쓴다.
- **곡률·모아레**(포스트프로세싱 트랙 잔여) — `MI_PP_ArcadeCRT` 의 `Curvature` 가 0으로 꺼져 있고
  스캔라인 모아레는 1080p 에서만 확인했다. 복셀 무기는 각진 엣지가 많아 **스캔라인과 간섭할 수 있다** —
  이 트랙 판정 때 같이 봐 두면 이득이다.
- **HUD 무기 아이콘** — DA 의 `WeaponIcon` 은 별도 2D 에셋이다. 복셀 룩에 맞는 아이콘이 따로 필요하다.
- **셀↔아웃라인 stencil 규약** — ADR 0007 미결. 무기에 아웃라인을 걸지 여부가 여기 걸린다.
