## §2 🔴 Blockbench 를 열기 전에 정할 것 — 나중에 못 고치는 것들

이 다섯 개는 **저작 자체의 규격**이라, 확정 전에 모델링을 시작하면 통째로 다시 만들어야 한다.
Claude 는 각 항목의 선택지와 근거를 정리해 사용자에게 **결정을 받아야 한다**(추측해서 진행 금지).

### 2-1. 복셀 1칸 = 몇 cm 인가 ★ 가장 중요
칸 크기가 곧 "얼마나 각져 보이는가"를 정한다. 칸 수 = 전장 ÷ 칸 크기.

🔴 **먼저 현행 라이플 전장을 실측할 것 — 이 문서는 그 수치를 갖고 있지 않다**(작성 시점에 에디터가
꺼져 있었다). 짐작으로 규격을 넘기면 §2 전체가 틀어진다. 에디터를 켜고:
```python
sk = unreal.EditorAssetLibrary.load_asset(
    "/Game/PolygonMilitary/Meshes/Weapons/Modular/Weapon_A/SK_Wep_Mod_A_Body_01")
e = sk.get_bounds().box_extent
print("full size cm:", e.x*2, e.y*2, e.z*2)   # 최장축 = 전장
```
⚠️ 이건 **몸통 파트만**이다. 총열·개머리판이 별도 파트라면 실제 전장은 더 길다 —
조립된 상태(PIE 또는 무기 조립툴)에서 재는 편이 정확하다.

전장 `L` 을 잰 뒤 이 표로 판단한다:

| 칸 크기 | 전장 칸 수 | 인상 |
|---|---|---|
| 5cm | `L`/5 | 매우 굵음. 강한 복셀 정체성, 디테일 표현 거의 불가 |
| 2.5cm | `L`/2.5 | 중간. 조준경·탄창 실루엣이 겨우 구분됨 |
| 1cm | `L`/1 | 거의 매끈. "복셀"로 안 읽힐 수 있음 |

⚠️ **1인칭 무기는 카메라에서 30~50cm 앞에 있다.** 같은 칸 크기라도 월드 오브젝트보다 훨씬 크게
읽힌다 — 아레나 셀이 200cm, 적 캡슐이 80×180cm 인 것과 **직접 비교하면 안 된다.**
결정 후 `Docs/SSOT/ArtDirection.md` 에 규격으로 남길 것(적·환경 복셀도 같은 격자를 써야 한다).

### 2-2. 총구가 향하는 축을 무엇으로 저작할 것인가
현행 DA 는 `ADSAimRotationOffset = Yaw 90` 인데, 이건 **Synty 팩의 총구가 +Y 라서** 넣은 보정값이다.
복셀 라이플을 **+X 정면**으로 저작하면 이 값은 **0 이 되어야 한다.** 반대로 그대로 두면 ADS 에서
총이 90도 틀어진다. → **저작 축을 먼저 정하고, DA 값을 거기 맞춘다.** (권장 = +X, 보정값 제거)

### 2-3. 색을 텍스처로 넣을 것인가, 머티리얼로 넣을 것인가 — ✅ **결정됨: B안** (사용자, 2026-09-03)
지금 아케이드 룩은 **텍스처가 한 장도 없다** — 바닥·벽·적 전부 절차적 머티리얼이다
(`MI_Pac_FloorGuide`·`MI_Pac_WallEdge`·`MI_EnemyProto_AtomCubes`). 무기만 텍스처를 쓰면
**혼자 다른 재질 언어**가 되고, 발광·림을 텍스처에 구워야 해서 셰이더가 내는 아케이드 효과와 어긋난다.

> ✅ **채택 = B. 색 구역을 머티리얼 슬롯으로 분리한다.** 몸통/총열/그립/발광부 정도로 나눠 각각
> 절차적 MI 를 물린다. 발광·엣지를 **셰이더가 낸다** → §4-1 색 규약을 코드로 지킬 수 있고,
> 적·환경과 같은 언어를 쓴다. 대가 = **색 수가 슬롯 수로 제한**되고, Blockbench 쪽에서
> **면을 그룹으로 나눠 익스포트**해야 한다.
> ❌ 기각 = A(Blockbench 텍스처 아틀라스). 저작은 쉽지만 위 이유로 룩 일관성을 깬다.

#### 🔴 B안이 성립하려면 먼저 확인할 것 (이 문서는 실측하지 않았다)
**Blockbench 가 머티리얼 그룹을 여러 개로 나눠 내보낼 수 있는가?** 여기서 막히면 B안은 설계대로
안 돌아간다. **모델링을 시작하기 전에** 작은 테스트 모델(2색 큐브 2개)로 왕복 검증할 것 —
전체를 만든 뒤에 알면 재저작이다.

확인 결과에 따른 사다리(위에서부터 시도):
1. **OBJ + 머티리얼 그룹** — 되면 그대로 간다. 임포트 선례가 OBJ 다(`import_enemy_proto_meshes.py`).
2. **glTF/GLB** — glTF 는 머티리얼별로 primitive 가 갈리므로 구조적으로 확실하다. 임포트도
   이미 실증돼 있다(`Troubleshooting.md` D1-b — *"같은 GLB 가 크래시 없이 들어옴"*).
   ⚠️ 메모리 `glb-import-crash-use-fbx` 의 크래시는 **무거운 리그드 캐릭터** 사례라 정적 무기엔 해당 없다.
3. **색 구역별로 파일을 나눠 익스포트** — 슬롯이 아니라 **메시를 쪼개는** 방식. 투박해 보이지만
   §2-4 에서 **파츠 분리를 택하면 어차피 이 형태가 된다**(파츠는 각자 자기 메시·자기 머티리얼이다).
   → **§2-3 과 §2-4 는 같이 정하는 게 싸다.**

### 2-4. 한 덩어리인가, 파츠로 쪼갤 것인가
모듈러/진화 시스템은 **파츠가 이미 정적 메시**이고 무기 메시의 **고정 소켓**에 붙는다.
- **한 덩어리** = 지금 당장 제일 단순. 진화로 총 모양이 바뀌는 연출은 못 한다.
- **파츠 분리**(몸통 + 총열 + 조준경 + 탄창) = 진화·모듈러가 그대로 살고, 나중에 노리쇠 애니도 가능.
  대신 **소켓 정합을 사용자가 Blockbench 쪽에서 맞춰야** 한다.

→ 라이플이 이 게임의 **기준 무기**라면 파츠 분리가 장기적으로 싸다. 사용자 결정.

### 2-5. 이 라이플이 파일럿인가, 1종만인가
복셀로 갈아엎으면 나머지 무기 8종(`DA_Weapon_{Shotgun,SMG,LMG,Sniper,Bazooka,ChargeLaser,Knife,Unarmed}`)이
**섞인 룩**이 된다. 라이플 하나만 먼저 만들어 판정하는 **파일럿**으로 갈지, 아니면 전량 교체 계획을
같이 세울지 정해야 한다. → 파일럿 권장(U21 Synty 파일럿과 같은 방식).

## §3 작업 순서

### 3-0. 결정 (에디터 무관)
§2 중 **2-3 은 확정됐다(B안 = 머티리얼 슬롯)**. 남은 **네 항목**(2-1 칸 크기 · 2-2 정면 축 ·
2-4 파츠 분할 · 2-5 파일럿 여부)을 사용자와 확정하고 **문서에 적는다.**
여기서 추측으로 넘어가면 뒤가 전부 재작업이다.

**먼저 할 두 가지** — 둘 다 모델링 시작 전에 끝나야 한다:
1. **라이플 전장 실측**(§2-1 코드) — 칸 크기 결정의 입력값이다.
2. **Blockbench 머티리얼 그룹 왕복 테스트**(§2-3 사다리) — 2색 큐브 2개짜리 최소 모델로.
   결과가 §2-4(파츠 분할)의 답도 같이 바꾼다.

### 3-1. 사용자 저작 (Blockbench, 프로젝트 밖)
Claude 는 §2 결정을 **규격서 한 장**으로 정리해 넘긴다: 칸 크기 · 전장 · 정면 축 · 머티리얼 그룹 이름 ·
파츠 분할 · 소켓을 놓을 위치(총구 끝, 조준선, 양손 그립).
사용자가 익스포트한 파일을 `Saved/RifleVoxel/` 에 둔다(선례 = `Saved/EnemyProto/`).

### 3-2. 임포트 (🔴 **에디터 꺼짐** — §5-1)
`Scripts/import_enemy_proto_meshes.py` 를 템플릿으로 `Scripts/import_rifle_voxel.py` 를 만든다.
실행은 **헤드리스 정식 에디터**:
```bash
UnrealEditor-Cmd.exe <uproject> -nullrhi -unattended -nosplash -ExecCmds="py Scripts/import_rifle_voxel.py"
```
목적지 = `/Game/Assets/Weapons/RifleVoxel/`(적 프로토가 `/Game/Assets/Characters/EnemyProto/` 인 것과 대칭).
판정은 **종료 코드가 아니라 로그의 완료 마커**로(§5-2).

### 3-3. 소켓 (에디터 켜짐 또는 헤드리스)
`SOCKET_Muzzle` · `SOCKET_Aim` · `SOCKET_LeftHand` · `SOCKET_RightHand` 를 메시에 만든다.
⚠️ 정적 메시의 소켓은 `UStaticMesh::Sockets` 이고 스켈레탈과 API가 다르다.
⚠️ 스켈레탈 쪽 함정(소켓이 메시가 아니라 **스켈레톤**에 산다 — 메모리 `arms-socket-lives-on-skeleton`)은
정적 메시엔 해당 없지만, **바디 쪽 `SOCKET_Weapon` 은 여전히 캐릭터 스켈레톤에 있다.**

### 3-4. 머티리얼 (에디터 켜짐 — 라이브 생성·편집은 안전)
**B안 확정이므로 텍스처를 만들지 않는다.** 슬롯별 절차적 MI 를 물린다 —
레시피는 `MI_Pac_WallEdge`(모서리 발광)·`MI_EnemyProto_AtomCubes`(프레넬 실루엣 림 +
노멀 변화율 하드 엣지)를 그대로 가져다 쓴다. 무기는 각진 면이 많아 **하드 엣지 레시피가 특히 잘 맞는다.**

슬롯 배분 초안(§2-4 파츠 결정과 맞물린다): `Body` · `Barrel` · `Grip` · `Emissive`.
발광 슬롯은 §4-2 대로 **작은 면적에만** — 총열 히트싱크·조준경 도트 정도.

색은 §4-1 대역(**V 25–70 · S 30–60**) 안에서, §4-1 의 🔒 예약색 회피 규칙을 지킨다.
머티리얼 검증은 **`get_statistics` 를 쓰지 말고** `get_material_diagnostics()` +
`export_material_graph()` 로(§5-3).

### 3-5. DA 배선 (에디터 켜짐)
`DA_Weapon_Rifle` 에서 — `WeaponMesh` 를 비우고 `WeaponMeshStatic` 에 복셀 메시를 넣는다
(스켈레탈이 우선이라 **비우지 않으면 복셀이 안 보인다**, `:2306-2308`).
`ADSAimRotationOffset` 을 §2-2 결정대로 고친다. 소켓 이름 5종을 실제 저작한 이름과 맞춘다.
> ⚠️ DataAsset 값 저작은 원래 **사용자 작업**이다(메모리 `da-edits-are-user-work`).
> 값과 위치를 정리해 넘기고, 사용자가 직접 넣게 할 것.

### 3-6. 검증
- 정적: 임포트된 메시 섹션 수 · 소켓 존재 · 바운드(전장이 의도한 cm 인지) · DA 참조 무결
- 동적(**사용자 PIE**): §6 판정 기준

## §4 🔒 지켜야 하는 것

### 4-1. 색 대역 — `ArtDirection.md` A-1

🔒 **A-3-4(적 = 뜨거운 쪽) · A-3-5(플레이어·아군 = 차가운 쪽)의 고채도·고명도 색을 무기 메시에 쓰지 말 것.**

### 4-2. 스웜 가독성이 무기 화려함보다 위다
`ArtDirection A-5` = *"적 메시를 화려하게 만들지 말고 VFX 에 헤드룸을 남긴다"*.
1인칭 무기는 **화면 하단의 상시 점유물**이다. 여기가 밝고 화려하면 적 200~300 을 보는 대역을 깎아먹는다.
발광은 **작은 면적에 국소적으로**(총열 히트싱크·조준경 도트 정도).

### 4-3. 외부 팩 통합 절차를 건너뛰지 말 것
`Docs/AssetIntegration_Protocol.md` 의 4단계(DISCOVER → MAP INTENT → AUTHOR → VERIFY)가 상시 절차다.

(저작 전 규약 역설계)를 §2 가 대신한다.

## §5 함정 — 이 트랙에서 반드시 밟게 되는 것

### 5-1. 🔴 임포트는 **실행 모드를 틀리면 죽는다** (그리고 정답이 있다)
| 실행 모드 | 결과 |
|---|---|
| **라이브 에디터**(MCP/Python) | ❌ **게임 스레드 데드락.** 강제 종료 외 방법 없음 (`Troubleshooting.md` D1-a) |
| **`-run=pythonscript` 커맨드렛** | ❌ 임포트 직후 Slate 없어 어설션 즉사 (D1-b) |
| ✅ **헤드리스 정식 에디터** | ✅ `-nullrhi -unattended -nosplash -ExecCmds="py <script>"` — 실증 2026-08-14 |

⚠️ **`Docs/ArcadePostProcess_ResumePrompt.md` §4-1 은 이 지점에서 틀렸다.** 그 문서는
*"두 실행 컨텍스트 모두에서 죽는다 … 세 번째 우회를 찾지 말 것"* 이라고 적었는데, **세 번째 우회는
이미 존재하고 문서화돼 있었다**(`Troubleshooting.md` D1-b 말미). 그 세션은 그걸 못 찾은 것이다.
→ **텍스처가 필요해도 사용자에게 떠넘기지 말 것.** 헤드리스 정식 에디터로 들어간다.

### 5-2. 커맨드렛/헤드리스는 **종료 코드로 판정하면 안 된다**
`Troubleshooting.md` C4 — 작업은 끝났는데 마지막에 UI 동기화로 죽어 exit 3 이 나오는 경우가 많다.
→ 스크립트가 찍는 **완료 마커**와 **`does_asset_exist`**, 그리고 **`git status`** 로 판정.
`save_asset` 은 기본이 `only_if_is_dirty=True` 라 **로그엔 성공, 디스크는 그대로**가 된다 →
`only_if_is_dirty=False` + git 대조.

### 5-3. 머티리얼 검증에 `get_statistics` 를 쓰지 말 것
그래프를 바꿔도 **같은 숫자를 계속 돌려준다**(생성 시점 값 고정). 2026-09-03 에 `sin`/`cos` 8회 루프를
넣어도 `PS=85` 가 미동도 안 한 것으로 실증했다 — `Troubleshooting.md` **G14**.
→ `get_material_diagnostics()`(`.is_compiled_ok`/`.compile_errors`) + `export_material_graph()`(연결 전량).
배선은 전부 `link()` 헬퍼로 감싸 **실패를 수집**할 것 — `connect_material_expressions` 는 이름을 못 찾으면
**조용히 False** 다(**D10**).

### 5-4. 스케일 — FBX/glTF 는 미터↔cm 에서 100배로 어긋난다
메모리 `fbx-metre-cm-armature-scale-trap`. 임포트 직후 **바운드를 cm 로 찍어 §2-1 에서 정한 전장과
대조**할 것. "들어왔다"는 "맞게 들어왔다"가 아니다.

### 5-5. 스켈레톤을 대상으로 하는 임포트는 하지 말 것
기존 스켈레톤을 지정해 임포트하면 뼈가 안 맞을 때 **그 스켈레톤 에셋을 통째로 갈아엎는다**
(메모리 `ue-import-overwrites-target-skeleton`). 이 트랙은 **정적 메시**라 해당 없지만,
§2-4 에서 스켈레탈로 방향을 틀면 그때는 **사람이 에디터에서** 해야 한다.

### 5-6. 열린 에디터가 `.uasset` 을 잠근다
임포트/머지 전 **에디터 종료**. 메모리 `ue-editor-file-locks-block-git`.

## §6 판정 기준 (사용자 PIE)

1. **크기가 맞는가** — 화면에서 총이 차지하는 면적이 종전 Synty 라이플과 비슷한가
2. **ADS 에서 조준선이 화면 중앙에 오는가** — §2-2 축 결정과 `ADSAimRotationOffset` 이 맞물렸는지
3. **총구 화염이 총구 끝에서 나는가** — `MuzzleSocket` 위치
4. **양손이 총을 잡고 있는가** — 좌/우손 IK 소켓
5. **적이 여전히 먼저 눈에 들어오는가** — §4-2. 무기가 시선을 뺏으면 실패다
6. **복셀로 읽히는가** — §2-1 칸 크기 판정. "각져 보이긴 하는데 복셀은 아닌" 상태가 제일 흔한 실패

## §7 미결 / 이 트랙 밖

- **나머지 무기 8종** — §2-5 에서 파일럿으로 정하면 여기로 이월된다.
- **적·환경 복셀 격자** — §2-1 에서 정한 칸 크기는 무기만의 것이 아니다. `ArtDirection.md` 에
  전역 규격으로 올려야 적/환경 저작이 같은 언어를 쓴다.
- **곡률·모아레**(포스트프로세싱 트랙 잔여) — `MI_PP_ArcadeCRT` 의 `Curvature` 가 0으로 꺼져 있고
  스캔라인 모아레는 1080p 에서만 확인했다. 복셀 무기는 각진 엣지가 많아 **스캔라인과 간섭할 수 있다** —
  이 트랙 판정 때 같이 봐 두면 이득이다.
- **HUD 무기 아이콘** — DA 의 `WeaponIcon` 은 별도 2D 에셋이다. 복셀 룩에 맞는 아이콘이 따로 필요하다.
- **셀↔아웃라인 stencil 규약** — ADR 0007 미결. 무기에 아웃라인을 걸지 여부가 여기 걸린다.
