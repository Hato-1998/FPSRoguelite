## 1. ⛔ 착수 전 막힌 것 — 콘텐츠 공백 4건

**실코드·실맵을 뒤져 확인한 것이다. 이거 안 채우면 아래 항목 중 절반이 실행 자체가 안 된다.**
(`d49998f2` 때 "억제기가 안 부서져서 검증 6개가 전부 실행 불가"였던 것과 같은 종류의 사전 점검이다.)

### 1-A. ✅ 해소 (2026-08-25) — `L_Map_2` 억제기 배치됨 · 아래는 해소 전 경위

`L_Map_1` 에는 배치 억제기 1개(`BP_Inhibitor_C_1`)가 있는데 `L_Map_2` 에는 파괴물이 **한 개도 없다**.
파괴물은 저작 배치 전용이다(런타임 스폰 경로 0건 — `SpawnActor<AFPSRArenaDestructible>` 검색 결과 없음).

**결과**: 스테이지1(`L_Map_1`) → 스테이지2(`L_Map_2`) 전환까지는 되는데, **스테이지2에서 나갈 방법이 없다.**
런이 아레나 2에서 보스 시간까지 갇힌다. 동시에 아래가 전부 검증 불가가 된다:

- 2회차 전환 (전환 상태기가 반복 호출에 견디는가)
- `AFPSRDestructible::ServerReset` — 재방문 아레나의 억제기가 intact 로 돌아오는가.
  이건 코드 주석이 *"이게 없으면 부서진 억제기가 영원히 부서진 채(체력 0, 파괴 불가) 남아 이후 모든 전환을 영구 차단한다"* 고
  명시한 **버그 수정 경로**다. 지금 구조상 실행이 안 된다.

**해제 조건**: `L_Map_2` 에 `BP_Inhibitor` 1개 배치(파괴 보상 = Stage Transition).

> ✅ **2026-08-25 해소 확인 (헤드리스 실측).** `e862ec07` 로 들어왔다. 커맨드렛으로 맵을 열어 잰 값:
> `L_Map_2` 에 `BP_Inhibitor` 1개 · 위치 `(-6770, 6370, 0)` · **Yaw 0** · 아레나 격자
> `x[-8000..8000] y[-8000..8000]` **안** · 파괴 보상 `FPSRDestructibleReward_StageTransition` 1개.
> **B5 실행 가능.**
>
> 🪤 이걸 재는 데 한 번 헛짚었다 — `.uasset` 은 **Git LFS** 라 `git show <커밋>:<경로>` 가 130바이트
> 포인터를 준다. 커밋 전/후 `grep` 비교는 **항상 "0개 → N개"** 로 나와 아무것도 증명하지 못한다.
> 유효한 판정 = 작업트리 실파일 + 에디터 리플렉션 읽기.
>
> 🟡 **다만 배치 높이가 `L_Map_1` 과 다르다** — 아래 §1-E 참조.

### 1-B. ✅ 해소 — `BP_Door` 폐지 (2026-08-24 사용자 결정)

문은 더 쓰지 않는다. **억제기가 대체**한다. 보드의 *"문 경로 실사격"* 항목도 삭제.

**단 검증 자체는 남는다 — 대상만 바뀐다.** 문이 파괴물과 달랐던 유일한 지점이 *"부서질 때 플로우필드 이음매를
연다"* 인데, `AFPSRArenaDestructible` 도 **같은 함수를 부른다**(`HandleBrokenAuthority` → `NotifyArenaCellsOpened`).
→ **A5 를 샌드백 파괴물로 재조준**했다. 문 배치 없이도 이음매 개방이 검증된다.

> 잔여: `AFPSRDoor` / `BP_Door` 는 이제 참조 0인 죽은 경로가 된다(`AFPSRDestructible` 이 원래 여기서 추출된
> 클래스다). 제거는 별건 — **정리 행 후보**.

### 1-C. ✅ 해소 — 억제기는 맵당 1개 확정 (2026-08-24 사용자 결정)

다중 억제기 / 폭발 동시 파괴 케이스는 발생하지 않는다. **B6 삭제.**
`RequestTransition()` 의 "두 번째 이후 요청 무시" 코드는 안전망으로 남지만 검증 대상이 아니다.

### 1-D. 🟡 억제기에 **피격 피드백이 하나도 없다** — 다만 체력바는 비목표다

두 가지를 구분해야 한다. 앞서 이 항목을 "체력바가 없다"로 적었는데 **그건 틀린 요구**였다:

**(a) 억제기 파손 연출 — 미저작.**
사용자 방침(2026-08-24) = **체력바는 안 띄운다. 체력 단계마다 망가져 가는 메시로 교체만 한다**(정확히 알리지 않기 위함).
코드 인프라는 이미 다 있다:
- `DamageStageThresholds` 기본 `{0.75, 0.5, 0.25, 0.05}` = 75/50/25/5% 에서 단계 발화
- `OnDestructibleDamageStage(StageIndex, HealthPct, Threshold)` = BP 이벤트
- `DamageStage` 는 **복제**되고 `OnRep_DamageStage` 가 클라에서도 같은 단계를 발화 → 메시 교체가 자동으로 전원에게 보인다

문제는 **`BP_Inhibitor` 가 이 이벤트를 하나도 안 받고 있다**는 것. 메시도 엔진 `BasicShapes` 플레이스홀더다.
→ 지금은 5000 HP 를 52초 동안 쏘는 내내 **화면 피드백이 0**이다. **콘텐츠 저작 행 후보**(파손 메시 4단계).

**(b) 딜링 창 카운트다운 — 후속 UI 작업으로 분리** (2026-08-24 사용자 결정).
`AFPSRGameState::GetStageDealingRemaining()` 을 읽는 위젯이 0개고, ADR 0010 실패흐름 1 이 요구한
*"`Pending` 대기 UI 큐"* 도 없다. **이번 검증 범위 밖** — D1 은 로그 + 스톱워치로 판정한다.

### 1-E. 🆕 2026-08-25 사전점검이 새로 잡은 것 4건 (전부 헤드리스 실측)

착수 직전에 커맨드렛으로 맵·에셋을 직접 열어 쟀다. **네 건 다 PIE 를 한 라운드씩 태울 것들이었다.**

**F1 🔴 지상 적에게 파괴물은 존재하지 않는다 — 이 행이 검증하려던 D7 동작 자체가 안 돈다.**
억제기 메시 오브젝트 타입 = `ECC_DESTRUCTIBLE`(16) *(대조군: 같은 레벨 일반 지오메트리 = `ECC_WORLD_STATIC`(0))*.
2D 베이크는 `...ByObjectType` + `ObjParams={ECC_WorldStatic}` 로 프로브하므로(`FPSRFlowFieldComputer.cpp:1331`)
**오브젝트 타입으로 걸러서 아예 안 본다** — 억제기가 `ECC_WorldStatic` *채널*에 Block 으로 응답해도 소용없다.
→ 큐브가 선 셀 25개가 "걸을 수 있음"으로 구워지고, 파괴 시 `NotifyArenaCellsOpened` 는 **안 막혀 있던 셀을 여는**
무효 호출이 된다. 3D 복셀은 채택 시 스탬프가 있어 정상 — **2D 에만 대응물이 없었다**(ADR 0012 가 생성기를
은퇴시키며 생긴 공백). **수정 완료 — [ADR 0010 D7 정정(2026-08-25)](Architecture/0010-arena-topology-and-stage-transition.md) 참조.**

**F2 🟡 억제기 내구도가 50 이다 (문서·보드·커밋메시지는 5000).**
`BP_Inhibitor` CDO 실측 = **50.0** *(대조군: C++ 부모 CDO = 150.0 — 리플렉션이 제대로 읽고 있다는 증거)*.
`BP_Inhibitor.uasset` 을 건드린 마지막 커밋이 `2415e53f` *"Durability 5000 확정분"* 인데 에셋엔 50 이 들어 있다.
저작 데미지 환산 = **라이플 5발(0.6초) · 맨손 2대 · 스나이퍼/바주카/차지레이저 1발.**
D6 의 *"체력 ≈ 예상 DPS × 요구 시간 → 일찍 부수려 할수록 비싸다"* 축이 **성립하지 않는 상태**다.
→ **사용자 결정(2026-08-25): 검증 동안은 50 유지, A·B·C 군 끝나고 5000 으로 되돌린다.**
⚠️ 그래서 **D1(딜링 체감)은 5000 상태에서 다시 재야 한다** — 어차피 §9 이후로 미뤄져 있다.

**F3 🟡 `L_Map_2` 억제기가 바닥에 2.5 m 묻혀 있다.**
5 m 큐브인데 `L_Map_1` 은 Z=250(바닥 Z=0 에 정확히 앉음), `L_Map_2` 는 **Z=0** → 아래 절반이 바닥 밑.
→ **사용자 결정: Z 를 250 으로 고친다**(아래 준비 작업 P1).

**F4 🟡 절차서 §2-4 의 전제가 실저작값과 달랐다** — 딜링 창이 8 초가 아니라 **1 초**다. §2-4 표에 실측값을 채웠다.

- **아레나 격자 안**에 놓을 것. 밖이면 `AFPSRArenaDestructible` 이 소유 아레나를 공간으로 못 찾아 orphan 경고가 뜨고,
  부서져도 셀이 안 열린다.
- `셀 발자국(가로×세로)` 을 메시 크기에 맞출 것.
- ✅ **재베이크 불필요.** 아레나 베이크 해시는 `ECC_WorldStatic` 컴포넌트만 센다. 파괴물은 `ECC_FPSRDestructible` 이라
  **정의상 해시에 안 들어간다**(`FPSRArenaBakeHash.h` 주석이 명시). 파괴물을 추가/이동해도 마스크는 fresh 그대로다.
- ⚠️ `내구도(Durability)` 는 **EditDefaultsOnly** 라 배치 인스턴스별로 못 바꾼다 — BP 기본값이다.
  그래서 P4 는 인스턴스 편집이 아니라 **BP 복제**여야 한다(운영 억제기의 5000 을 건드리지 않으려고).
  반면 `파괴 보상(Rewards)` 은 `EditAnywhere` 라 **인스턴스별로** 비울 수 있다.

## 2. 공통 준비

### 2-1. 시작법

| 목적 | 방법 |
|---|---|
| 솔로 (§3·§4·§6) | 에디터에서 **`Content/Maps/L_Arena`** 열고 ▶ Play. 전역 GM(`BP_FPSRGameMode`)이 붙어 런이 바로 시작된다 |
| 2인 (§5) | **`L_Lobby`** 열고 ▶ Play (`PIE_ListenServer`, 클라 2). 준비 → 런 시작. 로비 GM 은 seamless 라 클라가 따라온다 |

- **ESC 금지** — PIE 에서 ESC 는 플레이 종료다.
- 테스트 끝나고 git 작업 할 거면 **에디터를 반드시 닫을 것**(열린 에디터가 `.umap` 락을 잡아 머지가 깨진다).

### 2-2. 로그 보는 법 — 이게 주 관측 수단이다

`Window > Output Log` 에서 **`FPSR`** 로 필터. 전환은 페이즈마다 한 줄씩 찍힌다:

```
[Stage] Transition phase -> N (phase-end server-t=...)
```

**N 은 enum 정수다:**

| N | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 페이즈 | `None` | `Pending` | `Grace` | `Swapping` | `FadeOut` | `FadeIn` |

**정상 전환 1회의 기대 로그 순서** (§4-B1 판정 기준):

```
[StageDirector] Transition requested — dealing window 8.0s.
[Stage] Transition phase -> 2          ← Grace (딜링 창 열림)
[FlowField] NotifyArenaCellsOpened: coalesced recompute done (topology generation now K).
[Stage] Transition phase -> 4          ← FadeOut
[Stage] Transition phase -> 3          ← Swapping (암전 유지 → 스왑)
[Spawn] CarryEnemiesToNewStage: carried N / released M (cap X, snap-failed Y).
[Stage] Transition phase -> 5          ← FadeIn
[StageDirector] Swap complete: <이전 경로> -> <다음 경로> (stage 1, seed S).
[Stage] Transition phase -> 0          ← None (전환 종료)
```

> `Swap complete` 가 `phase -> 5` **뒤에** 오는 게 정상이다(`EnterFadeIn()` 이 로그보다 먼저 실행된다).
> 아레나 액터 이름은 서브레벨마다 똑같이 `FPSRArenaActor_0` 이라 **경로(`GetPathName`)로 찍는다** — 서브레벨 부분이 다르면 제대로 건너간 것.

**나오면 안 되는 줄**

| 로그 | 뜻 |
|---|---|
| `Warning: Destination arena is not visible to N connection(s) yet` | 목적지 준비 대기 진입 — 솔로에서 나오면 파킹이 깨진 것 |
| `Error: Destination arena still not visible ... after 5.0s — swapping anyway` | 준비 게이트 타임아웃. 그 클라는 아레나가 늦게 뜬다 |
| `Error: Swap aborted: %s failed to regenerate` | 아레나 재생성 실패 |
| `Warning: %s has no authored player entry points (APlayerStart)` | 진입점 미저작 → 폴백 링 사용 |
| `Warning: Swap requested but no AFPSRArenaActor exists` | 아레나 액터 자체가 없음 |

### 2-3. 쓸 콘솔 명령

| 명령 | 용도 |
|---|---|
| `FPSR.RunDebug 1` | 화면 오버레이 (런 시각 / alive / target / TimeScale). **스테이지 페이즈는 안 나온다** |
| `FPSR.SpawnEnemies [수] [반경=600]` | 적 버스트 스폰. 밀도·이월 테스트용 (예: `FPSR.SpawnEnemies 150 6000`) |

| `FPSR.KillAllEnemies` | 전 적 풀 반납 |
| `FPSR.AddXP [양]` | 강제 레벨업 → 카드 프리즈 유발 · 차지 레이저 카드 뽑기 |
| `FPSR.FlowField.Debug 1` | 플로우 화살표 + 막힌 셀 표시 (문/파괴물 이음매 판정용) |

| `FPSR.Debug.WeaponDraw 1` | 사격 트레이스 / 근접 히트 스피어 시각화 |
| `FPSR.RunTimeScale [배]` | 런 클럭 가속 |
| `stat unit` / `stat game` / `stat levels` / `memreport -full` | §6-D3 비용 측정 |

⚠️ **적 동시 생존 상한 = 200 (`GlobalAliveCap`, 컴파일 상수)** — 시드 예비분을 빼면 실측 상한은 ~192다.
`MaxAliveCount=300` 을 스케줄에 적어도 300 은 안 나온다. §6-D2 밀도 판정 때 이 상한을 전제로 볼 것.

### 2-4. 시작 전에 적어 둘 것 — `DA_RunSchedule` 의 전환 타이밍 6개

`Content/Game/Data/DA_RunSchedule` 을 열어 아래 값을 **먼저 적어 둔다.** 이게 §4·§5 의 기대 시간이다.
(괄호 = 스케줄 에셋이 없을 때 C++ 폴백. 저작값이 다르면 저작값이 기준이다.)

| 필드 | C++ 폴백 | **실측 저작값 (2026-08-25)** | |
|---|---|---|---|
| `StageGraceSeconds` (딜링 창) | 8.0 s | **1.0 s** | 🔴 P5 로 임시 8.0 상향 |
| `StageFadeOutSeconds` | 0.8 s | **2.0 s** | |
| `StageBlackoutHoldSeconds` (암전 유지) | 0.5 s | **5.0 s** | 폴백의 10배 |
| `StageSwapReadyTimeoutSeconds` (전원 준비 상한) | 5.0 s | 5.0 s | 폴백과 같음 |
| `StageFadeInSeconds` | 0.8 s | **2.0 s** | |
| `StagePostSwapGraceSeconds` (스왑 후 무적) | 1.0 s | 1.0 s | 폴백과 같음 |
| `StageCarryOverMaxFraction` (이월 상한) | 1.0 | 1.0 | 폴백과 같음 → B3 의 `released` 는 0 이어야 |

**전환 총 길이(정상, 대기 0) = 딜링 + 페이드아웃 + 암전유지 + 페이드인 = 10.0 s** (저작값 기준).
**그중 5초가 암전**이고 딜링 창은 1초다 — B1 의 구간 길이 판정은 이 값들과 ±0.2 s 로 맞춰 본다.

> 🔴 **딜링 1초로는 B2·B7 이 실행되지 않는다** (창이 열린 걸 인지하고 조작할 시간이 없다).
> **사용자 결정(2026-08-25): 검증 동안만 8.0 으로 올리고(P5) 판정이 끝나면 1.0 으로 되돌린다.**
> 게이트가 **작동하는가**(B2·B7)와 8초가 **적절한가**(D1)는 다른 질문이고, 후자는 §9 이후로 미뤄져 있다.
> 되돌리는 것을 잊지 말 것 — 되돌린 뒤 값이 1.0 인지 §7 기록표 아래에 확인 표시를 남긴다.

## 8. 결함이 나오면

- **로그 줄을 그대로** 붙일 것 — 위 표의 "나오면 안 되는 줄" 은 대부분 원인이 특정된다.
- 페이즈 숫자 순서가 기대와 다르면 **그 순서 그대로** 적을 것(어느 페이즈에서 새는지가 곧 범인이다).
- "값을 바꿨는데 안 변한다" 류는 **실행 경로부터** 의심할 것 — 1인칭 무기/파괴물 경로엔 경고 없이 조용히 꺼지는 게이트가 여럿 있다.
- 판정은 **대조군과 함께**. A7(히트스캔)이 같이 실패하면 그건 파괴물 문제가 아니라 측정 조건 문제다.

### 이 문서를 만들며 같이 발견된 것 (코드 수정 없음, 기록만)

1. **`FPSRCharacter.cpp` 의 스테일 주석** — 스왑 후 grace 를 설명하는 주석이 아직
   *"잔존 스웜은 스왑 커밋 전에 풀로 반납되므로(PerformSwap step 6) 남는 게 없다"* 라고 적혀 있다.
   Phase A 에서 반납 → **이월**로 바뀌었으므로 근거 문장이 낡았다. 결론(= `bPaused` 로 키잉)은 여전히 맞고,
   전환 케이스는 `StagePostSwapGraceSeconds` 가 따로 덮는다. **동작 영향 없음 · 주석만 낡음.**
2. **`Durability` 의 주석/스펙 불일치** — 주석은 *"배치 인스턴스별로 튜닝"* 인데 지정자는 `EditDefaultsOnly` 라
   인스턴스별로 못 바꾼다. **동작 영향 없음 · 주석만 틀림.**

## 9. 2026-08-24 사용자 설계 결정 — 3·4 는 **이 행 범위 밖, 새 작업**

### 9-1 ✅ 반영 — 억제기는 체력바를 안 띄우고 **파손 메시 단계 교체**만 한다

정확히 알리지 않는 것이 의도다. 코드 인프라는 이미 다 있고(§1-D (a)) **저작만 비어 있다.**

### 9-2 ✅ 반영 — 전환 중 UI(딜링 카운트다운)는 후속 UI 작업으로 분리

이번 검증 범위 밖. D1 은 로그 + 스톱워치로 판정한다.

### 9-3 🆕 아레나 = **랜덤 풀 추첨** (현재는 순차 순환 — 구현 필요)

**현재**: `NextArenaIndex = (현재 + 1) % 개수` · `UFPSRArenaStreamSubsystem::GetNextStageOrder` 가
`StageOrder` 오름차순 로스터를 **순차 순환**한다. 맵 2개면 `1→2→1→2…` 고정.

**의도**: 아레나 맵을 여러 개 만들어 두고 **억제기를 부술 때 풀에서 랜덤 1개**.

> ⚠️ **추첨 "시점"이 이 설계의 핵심이다.**
> ADR 0012 축 5 는 다음 아레나를 **한 스테이지 앞서 파킹**해서 전환 창을 고정 시간으로 만든다
> (`RequestParkAfter`, `PerformSwap` 8단계). 추첨을 **억제기가 부서지는 순간**에 하면 목적지가 파킹돼
> 있지 않아 매 전환마다 `Destination arena is not visible...` 대기(상한 5초)에 걸리고,
> **불변식 8(고정 시간 보상 창)이 깨진다.**
> → 추첨은 **직전 스테이지에 진입하는 시점(= 파킹 시점)** 에 해야 한다. 어디로 갈지 미리 모르는 건 똑같으니
> 플레이어 체감은 동일하다.

**같이 봐야 할 것**
- **결정론**(불변식 10): 서버가 `FRandomStream(스테이지 시드)` 로 뽑고 결과를 복제. — 지금 `ComputeStageSeed`
  (`BaseSeed + 스테이지×7919`)가 계산만 되고 **쓰이는 데가 없다**(베이크 아레나는 시드를 무시). 이 추첨이
  **그 시드의 첫 실사용처**가 된다.
- 직전 아레나 연속 추첨을 막을지 / 풀이 1개일 때의 동작
- 재방문 시 `AFPSRDestructible::ServerReset` 복원은 그대로 유효
- **동시 상주는 여전히 2개**(현재 + 파킹 1) → 풀이 커져도 D3 비용은 안 늘어난다. 늘어나는 건 `MapsToCook` 뿐

### 9-4 🆕 억제기 파괴 = **스테이지 난이도 축** (현재 없음 — 구현 필요)

**현재**: 난이도 축이 **파티 레벨 하나뿐**이다.
`AliveCountByLevel`(파티 레벨 → 동시 생존 적 수) + 적 종류 추첨도 `PartyLevel` 을 본다.
`GetStageIndex()` 를 읽는 곳은 **자기를 +1 하는 줄 1곳뿐** — 스테이지는 난이도에 전혀 관여하지 않는다.

**의도**: 억제기를 부술 때마다(= 스테이지가 오를 때마다) **파티 레벨과 별개로** 난이도가 오른다.

**기존 인프라로 갈 수 있는 자리** (새 매니저를 만들 필요 없음)
- `UFPSRRunScheduleDataAsset` 에 스테이지 축 추가 — `AliveCountByLevel` 과 같은 piecewise 형태로
- 적 로스터 컨텍스트(`FFPSRRunContext`)에 `StageIndex` 추가 → 상위 티어 적 해금을 스테이지로도 열 수 있다
- 억제기 `Durability` 도 스테이지에 따라 오르는 것이 ADR 0010 D6 의 *"일찍 부수려 할수록 비싸다"* 와 정합

> ⚠️ **곱하는 축이 3개가 된다.** 적 마릿수는 이미 `FPSREnemyAllocator::Apportion` 이 **인원수**로 배분하고,
> 여기에 인원수별 체력 스케일(별도 보드 행)을 얹으면 이중이다 — **스테이지 축까지 곱하면 3중**.
> WorkLog 가 이미 *"두 계수는 반드시 함께 봐야 한다"* 고 적어 뒀다. 플랜에서 셋을 한 번에 볼 것.

**되돌리기 비용**: ADR 0010 D6 은 "체력 = 비용 축"만 정했고 스테이지별 난이도 곡선은 안 정했다.
→ **ADR 0010 개정 또는 신규 ADR** 대상(구조 결정).
