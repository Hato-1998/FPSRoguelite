# 저작 시트 쓰기 — 설정과 사용 (정본 = 구글 시트)

> **왜 있는가**: 2026-09-05~09-13 사이 리포 CSV 가 저작 정본이던 기간이 있었다 — 유일한 사유는 "자동화가 시트에
> 못 쓴다"였다. Sheets API 서비스 계정 쓰기 경로가 생기면서 2026-09-13 정본이 **구글 시트**로 복귀했다(9/5~9/13
> 리포 CSV 정본 기간 종료). 이 문서는 그 쓰기 경로의 1회 설정과 일상 사용법이다.
>
> 관련: `Docs/SSOT/Localization.md` L-5(동기화 규약) · `Docs/SSOT/CombatWeaponCard.md` §2-3-10(카드 CSV 파이프라인) ·
> 명세 `Docs/Specs/SHEET1_SheetsApiWritePath.md`

## 0. 한눈에

```
사람 ── 시트에서 직접 편집 ─────────────┐
자동화 ─ authoring_sheet.py apply ──────┤──▶ 구글 시트(정본) ──sync-authoring-csv.ps1──▶ Content/**/*.csv(스냅샷, git) ──▶ 임포터·StringTable
                                        │                          ▲ apply 가 끝에 스스로 부른다
리포 → 시트 통째 교체 = seed(이관·복구 전용, 시트 무편집일 때만) ┘
```

- **리포 CSV 직접 편집 금지**(스냅샷이다 — sync 가 다음 실행 때 조용히 덮지 않고 막는다).
- 지금 상태는 `python Scripts/authoring_sheet.py status` 로 본다.
- 자동화 변경셋은 고치는 칸에 `expect`(현재 값)를 넣어 사람 편집과의 충돌을 미리 잡는다.
- **`apply` 가 도는 동안 시트에서 행 삽입·삭제·정렬 금지** — 인덱스가 밀려 엉뚱한 행에 쓰일 수 있다.

## 1. 1회 설정 — 사용자가 한다(약 10분, 비용 0)

> 결제 수단은 필요 없다. **이 구글 클라우드 프로젝트에 결제 계정을 연결하지 말 것** — 청구는 결제 계정으로 가므로 연결하지 않으면 청구될 곳이 없다. "무료 체험 시작" 안내가 떠도 건너뛴다. 결제 계정 없이 진행이 안 되는 화면이 나오면 멈추고 알린다.
> 이 리포의 현재 설정(2026-09-13): 프로젝트 `fpsrproject` · 서비스 계정 `fpsr-sheets-writer@fpsrproject.iam.gserviceaccount.com`. 새 머신은 키 파일만 옮기면 되고(1-5), 1-1~1-4·1-6 은 다시 할 필요가 없다.

1. **프로젝트 만들기** — 시트 소유 구글 계정으로 `https://console.cloud.google.com/projectcreate` → 프로젝트 이름(예: `fpsrproject`) → **만들기**.
2. **Sheets API 켜기** — `https://console.cloud.google.com/apis/library/sheets.googleapis.com` → 화면 맨 위 프로젝트 선택 칸이 방금 만든 프로젝트인지 확인 → **사용(Enable)**.
3. **서비스 계정 만들기** — 왼쪽 메뉴 **IAM 및 관리자(IAM & Admin) > 서비스 계정(Service Accounts)** → 위쪽 **+ 서비스 계정 만들기** → 이름 `fpsr-sheets-writer` → **만들고 계속하기** → 역할(권한) 단계는 **비워 두고** 계속 → **완료**. (시트 권한은 여기서가 아니라 6번 공유로 준다.)
4. **키 파일 받기** — 서비스 계정 목록에서 방금 만든 계정의 **이메일** 클릭 → 위쪽 **키(Keys)** 탭 → **키 추가(Add key) > 새 키 만들기(Create new key)** → **JSON** → **만들기**. 파일(`<프로젝트ID>-<영숫자>.json`)이 내려받아진다 — **다시 받을 수 없는 유일한 사본**이다. 잃어버리거나 새면 같은 탭에서 그 키를 **삭제**하고 새 키를 만든다.
5. **키 파일 두기** — 권장 = `C:\Users\<사용자>\.fpsr\sheets-service-account.json`(도구 기본 경로). 다른 곳에 두면 환경변수 `FPSR_SHEETS_SA_KEY` 에 전체 경로를 넣는다. **리포 폴더 안에는 두지 않는다**(도구가 거부한다). 클라우드 동기화 폴더(OneDrive 등)도 피한다.
6. **시트 공유** — 구글 드라이브에서 저작 시트를 **하나씩** 오른쪽 클릭 > **공유** → 서비스 계정 이메일을 넣고 권한 **편집자** → **알림 보내기 체크 해제** → **공유**. 새 테이블 시트를 만들면 그 시트도 같은 방법으로 공유한다.
7. 🚨 **공개 링크는 뷰어로** — 같은 공유 창 아래쪽 **일반 액세스**가 "링크가 있는 모든 사용자"면 오른쪽 권한을 반드시 **뷰어**로 둔다(**편집자 금지**). 이 리포는 공개라 시트 주소가 공개돼 있다 — 편집자면 누구나 정본을 고칠 수 있다. 폴더와 시트 각각 확인한다. (pull 은 공개 보기 링크를 쓰므로 "제한됨"으로 바꾸지는 않는다.)
8. **파이썬 라이브러리 설치** — 리포 루트에서 `python -m pip install -r Scripts/requirements-sheets.txt`.
9. **점검** — `python Scripts/authoring_sheet.py doctor` → 4줄 모두 `ACCESS OK · TABS 1 · CONTROL OK` 면 끝.

## 2. 일상 사용

키가 기본 경로(`~/.fpsr/sheets-service-account.json`)에 없는 머신(이 머신은 키가 바탕화면)은 먼저:

```powershell
$env:FPSR_SHEETS_SA_KEY = (Get-ChildItem "$env:USERPROFILE\Desktop\fpsrproject-*.json" | Select-Object -First 1).FullName
```

- **상태 확인**: `python Scripts/authoring_sheet.py status` — 시트 · 스냅샷(manifest) · 리포 CSV 3방향 비교. 자격 불요.
- **적용**: 먼저 `python Scripts/authoring_sheet.py apply <변경셋.json> --dry-run` 으로 계획을 확인한 뒤, 문제 없으면 `python Scripts/authoring_sheet.py apply <변경셋.json>`.

변경셋 형식(실물 예시 = `Content/Authoring/changesets/20260905-crit1-rifle-crit-build.json`):

```json
{
  "description": "왜 이 변경인가 — 감사 흔적으로 남는다",
  "changes": [
    { "sheet": "Cards",
      "upsert": [ { "CardId": "DA_Card_Foo", "Group": "Weapon", "E1_Attr": "weapon.firerate", "E1_Tiers": "C:0.03" } ],
      "delete": [ "DA_Card_Retired" ] }
  ]
}
```

사람이나 다른 세션이 같은 칸을 먼저 바꾸지 않았는지 확실히 하고 싶은 칸에는 `expect`(현재 값)를 곁들인다 — 값이 다르면 **아무것도 쓰지 않고** 실패한다:

```json
{ "CardId": "DA_Card_Foo", "E1_Tiers": "C:0.04", "expect": { "E1_Tiers": "C:0.03" } }
```

- **키 = 헤더의 첫 컬럼**(`"key"` 로 다른 컬럼을 지정할 수 있다).
- `upsert` 는 **병합**이다 — 준 컬럼만 덮어쓰고 나머지는 보존한다(새 행이면 빈 문자열).
- **한 변경셋에 같은 시트 항목은 하나만** — 둘 이상이면 거부된다.
- 사람이 시트에서 편집했으면 `sync-authoring-csv.ps1` 로 당겨 리포에 합친 뒤 커밋한다.
- `apply` 는 시트에 쓴 뒤 **끝에 스스로 sync 까지 돌려** 스냅샷을 갱신한다 — 따로 sync 를 부를 필요가 없다.
- 카드 시트(`Cards`)를 바꿨으면 마지막에 임포터를 돌린다(Tools > FPSR > 카드 CSV 임포트, 또는 `-run=FPSRImportCards`).
- **`seed`**(이관·복구 전용, `--confirm-replace` 필수, 시트가 마지막 pull 이후 무편집일 때만 또는 완전히 빈 새 시트일 때만 동작) — 리포 CSV 로 시트를 통째 교체한다. 일상적인 카드 추가·수정에는 쓰지 않는다.
- **새 테이블 추가** = 시트 생성 → 그 시트를 서비스 계정에 편집자로 공유 → `Config/AuthoringSheets.json` 에 매핑 1항목 추가 → 시트에 헤더를 직접 입력(또는 빈 시트에 `seed`) → `sync-authoring-csv.ps1` 로 첫 스냅샷 → 이후 `apply` 사용 가능.

## 3. 가드 표 — 무엇이 어떻게 지켜지는가

| 상황 | 어떻게 막는가 | 그래도 남는 틈 |
|---|---|---|
| 자동화 세션 두 개가 동시에 쓰거나, 쓰는 중에 사람이 sync 를 돌린다 | 잠금 파일(`~/.fpsr/authoring-sheet.lock`) — 먼저 잡은 쪽이 끝날 때까지 다른 쪽은 기다리지 않고 즉시 거부된다(끝난 뒤 다시 실행) | 같은 머신에선 없다. 다만 15분간 진행 신호가 없는 잠금은 죽은 것으로 보고 자동으로 치운다. 다른 머신에서 도는 자동화까지는 못 막는다 |
| 사람이 자동화가 고치려는 **바로 그 칸**을 동시에 편집한다 | 변경셋에 `expect`(현재 값 명시)를 넣으면 값이 다를 때 아무것도 안 쓰고 멈춘다 + 쓰기 직전에 한 번 더 읽어 확인한다 | 재조회한 순간과 실제로 쓰는 순간 사이(1초 미만)에 편집하면 그건 못 잡는다 — 마지막에 쓴 자동화 값이 남는다 |
| 사람이 **행을 넣거나 지우거나 순서를 바꾼다** | 쓰기 직전 재조회(표 전체 비교) + 쓴 뒤 되읽기(키 기준으로 차이 확인) | 재조회 뒤 1초 미만 사이에 행이 밀리면 엉뚱한 행에 쓰일 수 있다 — 되읽기가 사후에 잡아 종료 코드 3 으로 사람에게 넘긴다 |
| 한 시트에 쓰다가 중간에 실패한다 | 시트당 요청을 구글 API 의 원자적 `batchUpdate` 하나로 묶는다 — 절반만 적용되는 경우가 없다 | 없음 |
| 시트 여러 개에 쓰다가 뒤쪽 시트에서 실패한다 | 쓰기 전에 **모든 대상 시트를 먼저 읽고 계획을 검증**한다 — 데이터 오류라면 한 칸도 쓰기 전에 멈춘다 | 계획까진 통과했는데 실제로 쓰는 중 뒤쪽 시트에서 재조회 불일치·통신 오류가 나면 앞 시트는 이미 쓰였다 — 종료 코드 3 + 시트별 결과 보고 |
| 네트워크 응답이 유실돼 재시도했더니 두 번 적용된다 | 쓰기 요청은 서버 오류·통신 실패 시 **재시도하지 않는다**(결과 불명으로 사람에게 넘긴다) | 없음 |
| 리포 CSV 를 실수로 손으로 고쳤는데 pull 이 그걸 덮어 잃는다 | sync 의 LOCAL-AHEAD 가드 + manifest 기록이 없으면 아예 덮지 않는 가드(fail-closed) + `apply` 전제조건 검사 | 없음 |
| PowerShell 쪽과 Python 쪽이 서로 다른 manifest 파일을 본다 | 두 언어가 **같은 파생식**으로 manifest 경로를 계산 + 매번 `[manifest]` 로 출력 + 쓰기 뒤 사후 대조 | 없음(어긋나면 종료 코드 3) |
| `seed` 가 시트의 사람 편집을 지운다 | 시트가 마지막 pull 이후 무편집일 때(또는 완전히 빈 새 시트일 때)만 실행 허용 + 쓰기 직전 재조회 | 재조회 뒤 1초 미만 사이의 편집까지는 못 막는다 |
| 외부인이 공개 링크로 시트를 편집한다 | 공개 링크 권한을 **뷰어**로 고정(편집자 금지) | 없음 |

## 4. 갓차

① Claude(자동화)가 쓴 칸은 숫자처럼 보여도 **텍스트**로 들어간다 — 시트에서 계산에 쓰려면 `VALUE()` 로 감싼다.
② **시트 탭은 스프레드시트당 1개**를 유지한다(`Localization.md` L-5). export 는 gid 로 탭을 특정하는데, 탭이 여러 개면 gid 가 흔들려 sync 가 깨진 적이 있다.
③ 헤더에 없는 칸(헤더 밖 칸)에 값을 넣으면 `apply` 가 그 자리에서 거부한다 — 조용히 엉뚱한 열에 쓰이는 것보다 낫다.
④ **`apply` 가 도는 동안 시트에서 행 삽입·삭제·정렬 금지** — 인덱스가 밀려 엉뚱한 행에 쓰일 수 있다. 되읽기가 사후에 잡아내지만, 잡아낸 시점엔 이미 벌어진 뒤다.
⑤ **한국어 Excel 로 CSV 를 직접 열어 저장 금지** — CP949 로 저장돼 ko/ja 가 파손된다(`Localization.md` L-4). 편집은 시트나 이 도구로만 한다.
⑥ 셀 안 줄바꿈은 `\n` **리터럴 문자**로 쓴다(L-4) — 시트에서 실제 줄바꿈(Alt+Enter)을 넣지 않는다.
⑦ **키 파일 보안** — 유출되면 시트 4종 편집권이 새는 것과 같다. 유출 시 구글 클라우드 콘솔 > IAM 및 관리자 > 서비스 계정 > 해당 계정 > 키 탭에서 그 키를 **삭제**하고 새 키를 발급한다(§1-4).
⑧ **공개 링크는 항상 뷰어** — 이 리포가 공개라 시트 ID 도 공개다. 편집자로 바뀌어 있으면 인터넷의 누구나 정본을 고칠 수 있다.
⑨ **쿼터(분당 60회, 서비스 계정 기준)**·**결제 계정 미연결** — 표준 사용은 무료지만, 결제 계정을 연결하면 초과분이 청구될 수 있다. 연결하지 않는다.
⑩ 종료 코드 **3** = 쓰기가 일어났거나 일어났을 수 있는데 그 뒤가 실패했다는 뜻 — 시트는 **이미 바뀌었을 수 있다.** `python Scripts/authoring_sheet.py status` 로 확인한 뒤 필요하면 sync 로 리포에 반영한다.
⑪ "다른 세션이 시트를 쓰는 중" 오류 = 잠금이 남아 있다는 뜻 — 15분간 진행 신호가 없으면 자동으로 풀리고, 그 전까지는 `sync-authoring-csv.ps1` 도 함께 거부된다.

## 5. 아직 안 되는 것

- **게임 시작 시 시트 런타임 읽기** — 사용자 결정 대기(`Docs/Specs/SHEET1_SheetsApiWritePath.md` §2 비목표).
- **열 추가 명령** — 시트에 새 컬럼을 넣는 것은 사람이 시트 UI 에서 직접 한다. 자동화 명령은 없다.
- **시트→리포 자동 감지** — 사람이 시트에서 편집한 것은 `sync-authoring-csv.ps1` 을 누군가 돌려야 리포에 반영된다. 폴링이 필요해지면 별도 행.
