# 0004. 1인칭 팔 = 자체 스켈레톤 (S_Mannequin 이탈)

- 상태: 채택
- 날짜: 2026-08-04
- 되돌리기 비용: 비쌈 (스켈레톤 교체 = 메시·AnimBP·몽타주 전부 재바인딩)
- 보완 대상: [ADR 0003](0003-first-person-arms-camera-anchored.md) (불변식 전부 계승, 팔 스켈레톤 항목만 교체)

## 맥락

ADR 0003 은 1인칭 팔을 **PWAS 의 `S_Mannequin`** 에 바인딩했다. 근거는 *"PWAS 포즈를 그대로 쓴다"* 였다 — 포즈 에셋이 그 스켈레톤에 저작되어 있으니 메시도 거기 붙어야 했다.

그래서 `fp_arms_rebuild.py` 는 NEON-V 팔 메시를 **마네킹 뼈 위치에 맞춰 구부려** 구웠다. UE 는 스켈레톤을 공유하면 ref pose 도 공유하고, 메시 바인드가 ref pose 와 다르면 강제로 늘어나기 때문이다(ADR 0003 함정 3). 즉 **메시를 스켈레톤에 맞추는** 방향이었다.

**그 전제가 깨졌다.** 사용자 결정(2026-08-04): *"애니메이션을 안 쓰려고 지금 애니메이션도 다시 저작하려는 것"* — PWAS 포즈를 견본으로만 쓰고 최종 애니는 직접 저작한다. 포즈 에셋을 그대로 재생하지 않는다면 **S_Mannequin 에 묶여 있을 이유가 없다.**

ADR 0003 자신이 이 순간을 예고해 뒀다:

> *"무기군이 6종을 넘어 PWAS 포즈로 못 덮을 때 — 포즈 저작이 필요해진다. **그때 팔 포즈의 저작 파이프라인(어느 DCC, 어느 스켈레톤)을 정해야 한다**"* (ADR 0003, 재검토 조건)

그리고 기각안 목록에서 스켈레톤을 불변식에서 **명시적으로 제외**해 뒀다:

> *"팔 메시는 바디와 다른 스켈레톤이어야 한다 — 채택안이 우연히 만족하는 성질이지만 **불변식으로 쓰면 과하다**"*

## 문제 — 메시를 구부린 대가

사용자가 손가락 포즈를 저작하다 *"손가락이나 손이 왜 이렇게 늘어난 느낌이지"* 라고 지적했고, 실측으로 확인됐다.

| | 원본 NEON-V | 현재(마네킹 컨폼) | |
|---|---|---|---|
| **손바닥**(손목→손가락 뿌리) | 7.88~8.43cm | **8.90~9.75cm** | **+9~21%** |
| **손가락**(뿌리→끝) | 6.83~9.81cm | 6.71~8.84cm | **−7~10%** |
| 손 폭 | 6.42cm | 7.02cm | +9% |
| 손 전체 길이 | 14.92~17.67cm | 15.45~17.85cm | +1~3% |

전체 길이는 맞는데 **손바닥이 길어지고 손가락이 짧아졌다** — 그래서 늘어나 보인다.

**원인**: Manny 는 `hand → metacarpal → 01 → 02 → 03`, Blu 는 `hand → proximal → intermediate → distal`. 손가락 뼈는 3개로 같지만 **Manny 는 손바닥 안에 뼈가 하나 더 있어 손가락 뿌리가 손목에서 1.0~1.6cm 더 멀다.** rebuild 가 Blu 의 `proximal` 을 Manny 의 `01` 자리로 옮기며 그 차이만큼 손바닥을 늘렸다.

**이건 포즈로 못 고친다.** 메시와 바인드에 구워진 형태다.

## 결정

**1인칭 팔에 자체 스켈레톤을 준다.** 뼈 **이름과 계층은 Manny 그대로**(65본) 두고, **뼈 위치만 NEON-V 실제 해부에 맞춘다**. 손허리뼈는 손바닥 안 제자리로 간다.

방향을 뒤집는 것이다 — **메시를 스켈레톤에 맞추던 것을, 스켈레톤을 메시에 맞추는 쪽으로.** UE 의 "스켈레톤=ref pose 공유" 제약은 그대로 만족한다(스켈레톤을 메시에서 만드니 구조상 일치한다).

> 제1원리 3줄
> ① **1P 팔은 화면 중앙에 크게 보이는 단일 메시라 기준이 액터당 비용이 아니라 정확도다.** 손 왜곡은 그 기준을 정면으로 깬다.
> ② **엔진 기본값(스켈레톤=ref pose 공유)은 그대로 따른다.** 덮는 게 아니라, 그 제약을 만족시키는 방향을 뒤집을 뿐이다.
> ③ ADR 0003 이 명시한 재검토 조건에 도달했고, 그 ADR 자신이 S_Mannequin 을 불변식에서 제외해 뒀다.

### 유지하는 것

- **본 이름·계층 = Manny 65본 그대로.** 코드·AnimBP·소켓 로직이 안 바뀌고, 나중에 리타게팅도 열려 있다
- ADR 0003 의 불변식 전부(카메라 부착, 독립 애님그래프, 분할 판정, 무기 데이터 한 벌 …)
- 견본으로서의 PWAS 포즈 — **회전은 비율이 달라도 그대로 옮겨진다.** `fp_arms_pose_from_ref.py` 방식은 계속 유효하다

### 바꾸는 것

| | 전 | 후 |
|---|---|---|
| 팔 스켈레톤 | `/Game/ProceduralWeaponAnimationSystem/Demo/FPManny/S_Mannequin` | 자체 (경로 미정) |
| 뼈 위치 | Manny 비율 | NEON-V 해부 (범위는 아래 미결) |
| `SOCKET_Weapon` | S_Mannequin 의 것 (hand_r identity = **손목**) | 우리 것 (**손바닥**에 저작) |

## 얻는 것

1. **손 왜곡 소멸** — 손바닥 +9~21%, 손가락 −7~10% 가 사라진다
2. **소켓 소유권** — `SOCKET_Weapon` 이 손목이라 손잡이가 손목에 오던 문제(실측: 손잡이가 손바닥에서 6.03cm)를 처음부터 손바닥에 박아 없앤다
3. **PWAS 폴더 의존 해소** — ADR 0003 함정 1(*"PWAS 폴더를 지우면 팔 메시가 스켈레톤을 잃는다"*)이 사라진다

## 잃는 것 / 비용

- 팔 AnimBP 를 새 스켈레톤 대상으로 다시 잡아야 한다
- `SK_FP_Manny_Simple` 대비 **0/65 본 잔차 검증이 무의미해진다** — 그 검증은 S_Mannequin 에 맞추려던 것이라 목적 자체가 없어진다. **대체 검증을 새로 정해야 한다**(아래 미결)
- 팔 메시 재추출 → 재임포트 → 배선
- PWAS 몽타주를 나중에 쓰고 싶으면 리타게팅이 필요하다(지금 계획엔 없다)

## 🚨 미결 — 착수 전에 반드시 정할 것

**어디까지 NEON-V 비율로 되돌릴 것인가.** 팔 전체를 되돌리면 **소총을 두 손으로 못 잡는다.**

| | 원본 NEON-V | 현재(마네킹) | |
|---|---|---|---|
| 팔 도달(상완+전완) | **41.54cm** | 55.02cm | −24% |
| 상완 / 전완 | 19.89 / 21.65 | 27.77 / 27.25 | |
| 어깨(upperarm) 간격 | 28.09cm | 38.02cm | −26% |

소총의 왼손 그립(`SOCKET_LeftHand`)은 오른손에서 **43cm 앞**이다. 도달 41.5cm 로는 팔을 완전히 펴도 못 닿는다. 현재(55cm)에서도 총을 앞으로 밀면 모자랐다.

**선택지**

| | 내용 | 대가 |
|---|---|---|
| **A. 손만 되돌린다** | 팔 길이·어깨 간격은 마네킹 유지, **손 비율만 NEON-V** | 사용자가 지적한 왜곡(손)이 정확히 해소되고 도달 55cm 유지. 긴 팔 + 작은 손이라는 조합은 애니풍 캐릭터에 부자연스럽지 않다 |
| **B. 전부 되돌린다** | 팔·어깨까지 NEON-V | 두 손 파지 불가 → `SOCKET_LeftHand` 를 핸드가드 뒤로 크게 당기거나 `WeaponAttachScale`(현 0.85)을 더 줄여야 한다. **무기 데이터 전반에 영향** |
| **C. 중간** | 손 = NEON-V, 팔 = 원본과 마네킹 사이 | 조절 여지는 크지만 근거가 임의적이 된다 |

**권장 = A.** 사용자가 실제로 지적한 것이 손이고, 팔 길이는 1인칭에서 거의 안 보인다. B 는 무기 쪽 데이터를 연쇄로 건드린다.

## 미결 2 — 새 검증 기준

0/65 가 사라지면 *"메시가 제대로 들어갔는가"* 를 무엇으로 판정할지 다시 정해야 한다. 후보:

- **바인드 = ref pose 일치** — 스켈레톤을 메시에서 만들었으니 구조상 참이어야 한다. `Approx Size` 로 확인(이번에 단위 함정을 잡아낸 지표)
- **웨이트 커버리지** — 무가중 0 · 합 1 · twist/metacarpal 물림(기존 감사 그대로 유효)
- **포즈 이탈량** — 기준 메시가 없어지므로 **원본 NEON-V 대비**로 바꾼다(원래 이게 더 맞는 기준이었다)
