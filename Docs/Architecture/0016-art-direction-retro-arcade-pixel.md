## 맥락

2026-09-03 사용자가 월드 모티프를 **레트로 아케이드 사이버스페이스**로 돌렸고, 같은 날 아케이드 룩 프로토(아레나 코너 네온 격자 + CRT 포스트프로세스, 보드 「아케이드 룩 프로토 + 육안 게이트」 완료 `037e681f`)와 2026-09-05 복셀 유령 적 「쩝쩝이」 파일럿이 화면으로 방향을 확인했다. 그 프로토의 한계도 같이 보였다 — 지금 아레나는 **검은 면 + 발광 격자선**뿐이라 "Tron" 으로는 읽혀도 **"픽셀 게임"으로는 읽히지 않는다**. 쩝쩝이(복셀)와 아레나(선)가 다른 언어를 쓰고 있었다.

## 결정

**D1. 룩 = 레트로 아케이드 픽셀.** 픽셀은 세 층에 산다 — ① **형태 = 복셀**(3D 픽셀; 적·프롭·환경 블록·1P 무기) ② **평면 요소 = 픽셀 스프라이트**(VFX·픽업·UI 아이콘, 포인트 필터, 팔레트 제한) ③ **화면 = CRT 포스트프로세스**(스캔라인·색수차·비네트, 현행 `PP_Arcade` 값 유지: 스캔라인 270 · 강도 0.15 · 곡률 0). **화면 전체 저해상도 픽셀화는 쓰지 않는다**(I6).

**D2. 환경 = 어두운 무대, 팝은 액센트.** `§A-1` 대역표 무변(환경 V 6~40 · S 15~40). substrate 5색(`§A-3-1`, 바닥·블록·벽의 복셀 면)이 화면 70% 이상. 팝한 색(금·주황·연두·마젠타)은 합쳐 **화면 10% 미만**이고 자리가 정해져 있다 — 통행 정보(배선), 파괴물 코어, 픽업, VFX, UI, 경계벽 밖.

**D3. 면은 안, 패럴랙스는 밖. (정정 2026-09-06(b))** 플레이 공간(콜리전이 있는 모든 것) = **복셀 면** — 평면 채색 + 같은 대역 안의 어두운 격자선(복셀 경계). 밝은 선은 오직 **바닥 배선**(통행 가능 = 밝다, 0010 D8 — 사용자 2026-09-06 *"회로배선 유지해도 어울릴거같은데"*)만 든다. 경계벽 바깥(플레이 불가) = **픽셀 패럴랙스 배경** — 레트로 게임 배경 레이어(픽셀 별 · 먼 스카이라인 실루엣 · 부유 픽셀 블록), **전부 단색 실루엣**. 구역마다 레이어를 바꿔 무드를 변주한다. 마젠타는 여기서만 강하게(`§A-3-6`). **폐기**: Tron 네온 엣지 선 룩(블록·벽의 발광 테두리) · 와이어프레임 부유 기하 · 회로기판 트레이스/부품 픽션. 밋밋 방지 레버는 다섯으로 유지 — ① 구역 색 ② 밝기 대비 ③ 밀도 변주 ④ 배선 발광 ⑤ 실루엣(패럴랙스 레이어가 ①③⑤를 진다).

**D4. 복셀 격자 계층(제안 초기값, PIE 육안 조정 대상).**

| 클래스 | 격자 | 근거 |
|---|---|---|
| 환경(블로커·벽·프롭) | **5 cm** | 콜리전 셀 100cm · 문턱 45cm · 60cm 가 **전부 정수배**(20·9·12). 면은 평평, 격자는 머티리얼 선 — 지오메트리를 5cm 로 쪼개는 게 아니다 |
| 적·픽업 | **7.5 cm** | 쩝쩝이. 컨셉 시트 스프라이트 18층 = **135cm**(2차 메시 22층·165cm 는 3차 재설계로 폐기, 시트 스프라이트가 메시 정본). 먼 거리에서도 덩어리로 읽히는 굵기 |
| 1P 무기 | **2.5 cm** | 카메라 30~60cm 앞이라 적 격자의 1/3 — 화면상 픽셀 크기가 적과 비슷해진다 |

한 오브젝트 안에서 격자는 하나(I4). 클래스 사이의 격자 차이는 **거리가 화면 픽셀 크기를 맞춰 주므로** 허용한다.

**D5. 색 = `ArtDirection.md §A` 그대로. 레퍼런스 hue 의 재매핑 표는 `§B-2`.** 무기 악센트는 사용자 결정(2026-09-03)대로 **파란 계열**이며, `§A-3-5` 봉인 조항("환경·프롭·UI 장식 어디에도 고채도 아군색 금지")과의 충돌은 **예외 조항으로 명문화**한다 — **무기는 프롭이 아니라 캐릭터의 일부**다. 1P 무기 이미시브 = `#8B6BFF`(자기 자신), 3P 팀원 무기 = `#4FD8FF` 계열을 **채도 낮춰**(아군 아웃라인과 싸우지 않게). 무기가 월드에 놓이는 순간(드롭·상점 프롭이 생기면) 그건 프롭이라 UI 보상색(`#FFC24A`) 규칙을 따른다. 별도 블루를 발명하지 않는 이유 = 규칙 하나("파랑 = 우리 편")를 지키는 게 학습 비용이 싸다.

**D6. 픽션 어휘 = 게임 세계 다이브 + 수호자.** `Concept.md §1-C-9`(다이브) 위에 『전자오락수호대』 모티프를 얹는다: 플레이어 4인 = 접속한 히어로(차가운 색), 적 = 세계를 갉아먹는 **버그·글리치**(뜨거운 색), 억제기 = 스테이지를 지배하는 **캐비닛 코어**. 로그라이트 어휘의 아케이드 번역: 런 = 1코인 플레이 / 레벨업 카드 = 파워업 / 스테이지 전환 = **STAGE CLEAR**(`§A-2` Ultimate 자리) / DBNO = **CONTINUE? 카운트다운**(동료가 오면 멈춤) / 런 종료 = GAME OVER + 하이스코어. 문구는 콘텐츠(LOC0 String Table)지 코드가 아니다.

**D7. 제작 경로 = 셋, UE VoxWrap 은 배제.** ① **절차 생성**(파이썬 → OBJ, 쩝쩝이 방식) — 일반 적·프롭·반복물 ② **손 저작**(Blockbench 등 외부 DCC — 사용자 작업) — 보스·1P 무기·랜드마크 ③ **기존 메시 변환**(Blender Remesh > Blocks) — 후보, 결과가 크리스프 큐브인지 건별 확인. UE5 `ApplyMeshSolidify`(VoxWrap)는 결과가 둥글어 배제. **텍스처 없음** — 색 = 요소ID LUT(`floor(UV.u)` 계약, 쩝쩝이 12요소) 또는 정점색 + 격자선 + 이미시브. 사진·노이즈 텍스처 금지(`§A-5`).

**D8. 폰트 = 픽셀 폰트 2종 후보(후속 행에서 확정).** Latin·숫자 = Press Start 2P 계열(OFL) / 한글 = Galmuri 계열(OFL). 컨셉 시트는 Press Start 2P + Noto Sans KR 로 그렸다(한글 픽셀 폰트는 Google Fonts 에 없다). 확정은 LOC0 String Table 정합과 함께 별도 행.

**D9. 맵 = 팩맨 미로 기반 + 구석 특수 에리어 (사용자 결정 2026-09-06(c)).** 아레나 통로 형태는 `Scripts/gen_pacmaze_proto.py` 의 MAZE(28 × 31 타일, 통로 = 1타일 폭)를 기반으로 한다. 벽 = 복셀 면 + 상단 엣지 1줄, 통로 바닥 = 가운데 배선 1줄(가이드 라인, 정션 = 비아). **중앙 고스트 하우스 = 캐비닛 코어(억제기) + 글리치 스폰 자리**, 좌우 워프 터널 유지. **구석 4곳 = 특수 에리어**(지금은 없음 — 팩맨 파워 펠릿 자리, 구석 블록 3×3 을 파낸 방). 내용은 사용자 결정이고 컨셉 시트는 후보 4종(A 파워업 부스 = 카드 제단 / B CONTINUE 부스 = DBNO 부활·회복 / C 보너스 존 = 미션 HoldZone·CollectOrbs / D 무기 캐비닛 = 언락·교체)을 제안한다. 방 바닥은 substrate 안의 고유 틴트, 프레임·아이콘만 UI 대역.
> ⚠️ **이 결정이 여는 두 가지 — 이 문서 범위 밖, 별도 ADR(0017) 대상.** ① **규모**: 프로토 타일 10 m 면 280 × 310 m = ADR 0012 규모 상한(160 × 160 m · 25,600 셀)의 **약 3.4배**(86,800 셀). 타일 5 m(140 × 155 m)면 상한 안. 컨셉은 **비율만** 정한다. ② **위상**: ADR 0010 D1(다중 코어 교차 동선, 볼록 클러스터)이 **통로 미로**로 바뀐다 — 스타일이 아니라 위상 결정이고, 0012 불변식 1(베이크 스테일)·플로우필드 폭·스웜 동선이 전부 걸린다. 시각 부록 = 컨셉 시트 「아레나 맵 · 팩맨 미로」「통로 1P 뷰」.

**D10. 방향성 기준 이미지 = 사용자 제공 키아트 (정정 2026-09-06(d) · 최종안 (e)).** 최종 = `Docs/Concept/ArcadePixel_KeyArt_UserRef_2026-09-06_v2_HUD.png`(HUD 배치까지 프로젝트에 맞춘 사용자 최종안; v1 `..._2026-09-06.png` 은 기록). HUD 요소 ↔ 시스템 대조 = `ArtDirection.md §B-11`. — 사용자: *"내가 보고 있는 가장 이상적인 게임 모습. 최종 모습은 달라질 수 있지만 이 아트를 방향성으로."* 이미지는 **그대로 복제하지 않고 §A 색 규칙으로 번역**한다. 번역표(정본 = `ArtDirection.md §B-10`):

| 이미지 | 채택 | 번역(규칙 정합) |

## 근거 (핵심원칙 4 — 3줄)

1. **제1원리** — 이 게임의 화면은 *적 수백 마리를 읽는 1인칭*이다. 복셀은 **실루엣이 덩어리로 읽히고**(디테일이 격자로 제한되므로 노이즈가 생기지 않는다), 어두운 무대는 **VFX·적 코어·픽업의 헤드룸**을 남긴다. Tron §1 의 다섯 근거(디테일 텍스처 불필요 · 싸다 · 스웜 가독성 · 머티리얼 통일 · 블록 지오메트리 정합)는 아케이드 픽셀에서 전부 살아남고, 여기에 "픽셀 = 격자 하나로 저작 규칙이 정해진다"가 더해진다.
2. **엔진 기본값·기존 인프라와의 관계** — 렌더 경로는 **바꾸지 않는다.** 적 = 0007 의 공유 base material + CPD(`_Proc` 가 CPD 에 상태ID·진입시각·rate 를 쓰고, 읽는 쪽 = 복셀 머티리얼 WPO 가 그 빈 자리에 들어간다). 아레나 = 0012 의 "렌더 메시는 껍데기" 위에서 렌더 메시·머티리얼만 교체. 크로스헤어(U12 절차 SDF)·HUD 위젯 3종(세터·값 소스 유지, 스킨만)·`PP_Arcade`·쩝쩝이 파이프라인은 그대로 쓴다. 엔진의 스크린 정렬 픽셀화(머티리얼 PP 다운샘플)는 *오브젝트가 회전하면 깨지고 1P 무기가 최악*이라 쓰지 않는다 — 픽셀은 오브젝트에 붙는다.
3. **프로젝트 제약과의 정합** — 4인 협동 기준선: 아군 = 차가운 색 실루엣, 적 = 뜨거운 색 + 코어 1개 — 이 규칙은 룩과 독립이라 룩이 바뀌어도 협동 가독성이 무너지지 않는다. 서버권위·복제 무접촉(전부 렌더·콘텐츠). 콜리전 100cm 셀과 45/60cm 문턱이 환경 격자 5cm 의 정수배라 저작 규칙 하나로 두 세계가 맞는다.

## 검토한 대안

### 안 A — 화면 전체 저해상도 픽셀화 포스트프로세스 — **기각(사용자 결정 2026-09-06)**
가장 "픽셀 게임"처럼 보이는 지름길. 그러나 프레임 전체를 다운샘플하면 **크로스헤어 정밀도와 원거리 적(수 픽셀짜리) 판독**이 같이 깎이고, 픽셀이 화면에 정렬돼 오브젝트가 회전하면 표면 픽셀이 흐른다(1P 무기가 최악). 적 200~300 을 읽어야 하는 이 게임에서 정보 채널을 깎는 룩은 제1원리 위반. 근거리 전용·원거리 전용으로 나누는 혼합안도 경계 지글거림 리스크와 셰이더 비용이 추가돼 보류.

### 안 B — 중간 밝기 평면 채색(픽셀 게임처럼 환경도 밝게, 레퍼런스에 가깝게) — **기각(사용자 결정 2026-09-06)**
롤 아케이드의 팝한 인상에 가장 가깝다. 대가 = `§A-1` 대역표 개정 — 환경 V 를 50 근처로 올리면 캐릭터(V 25~70)·VFX 대역과 겹쳐 **적·VFX 헤드룸이 줄고** 스웜 가독성이 PIE 실측 없이는 보증되지 않는다. "어두운 무대 + 팝 액센트"가 같은 인상을 액센트 면적으로 내면서 대역표를 건드리지 않는다. 실측 후 환경 대역 상단을 5~10 올리는 정도는 후속 조정 범위.

### 안 C — 셀/툰(SRS) 전체 통일 룩 유지 — **폐기(2026-09-03 사용자 결정, 이 문서가 기록)**
2026-07-10 확정·07-18 U21 락. 폐기 사유 = 도시맵 트랙 자체가 ADR 0010 에서 기각되고 Synty 도시·무기 팩 콘텐츠가 삭제됐으며(`31fee185`), 아레나 위상에서 셀 아웃라인이 줄 이득(메시 디테일 정리)이 복셀에서는 격자 자체가 대신한다. SRS 스택(`srs-postprocess-stack-fog-haze`)·Custom Depth 실측(1.33ms)은 기록으로 유효.

### 안 D — Tron 선 룩(현행 프로토 그대로, 또는 경계 밖에만 잔존) — **기각(사용자 결정 2026-09-06(b))**
프로토 판정(2026-09-03)에서 "룩 방향은 맞다"가 나왔지만, 검은 면 + 발광 선만으로는 픽셀 게임으로 읽히지 않고 복셀 적과 언어가 갈린다. 이 문서 초안은 선 언어를 경계 밖(회로·와이어프레임)에 남기려 했으나 사용자가 **"전면 아케이드 픽셀, 나머지(Tron·회로기판) 폐기"** 로 결정했다. 바닥 배선 하나만 통행 신호로 남는다(모티프가 아니라 판독 규칙이라서). 프로토의 `PP_Arcade` 값과 아레나 코너 블록 배치는 재활용.

### 안 E — 스크린 정렬 픽셀 셰이더(오브젝트별 머티리얼에서 픽셀 스냅) — **기각**
복셀 메시 없이 머티리얼만으로 격자를 흉내내는 안. 실루엣을 못 바꾸므로 윤곽은 매끈한데 표면만 계단이 되어 **가짜 픽셀**로 읽힌다. 새 메시가 필요하다는 보드 조사 결론(2026-09-03)과 같다.

## 논의 중 제기된 반론

- **"격자 3종이면 그게 믹셀 아닌가"** — 픽셀 아트의 믹셀 금지는 *한 화면 안 한 평면*의 규칙이다. 3D 에서는 거리가 화면 픽셀 크기를 바꾸므로 클래스마다 격자를 달리 해야 오히려 화면에서 균일해진다(1P 무기 2.5cm 가 30cm 앞에서, 적 7.5cm 가 10m 밖에서 비슷한 화면 픽셀). 금지는 **한 오브젝트 안**에만 건다(I4).
- **"어두운 무대는 레퍼런스와 다르다"** — 맞다. 레퍼런스는 히어로 아트라 채도·명도를 다 쓴다(`§A-0` ①). 같은 인상을 내는 수단은 **밝은 것의 면적**이 아니라 **밝은 것의 자리**다 — 픽업·코어·UI·경계 밖이 팝하면 화면은 팝하게 읽힌다. 안 B 를 열어 두었으니 PIE 뒤 필요하면 대역 상단을 조정한다.
- **"복셀 메시는 폴리가 많다"** — 사실이다(쩝쩝이 4.6k tris). 다만 이 비용은 격자 크기가 아니라 **면 병합 여부**가 정한다. 절차 생성기에 greedy meshing 을 넣으면 같은 격자에서 tris 가 수 배 줄어든다 — 검증 시나리오 마지막 항목.
- **"무기에 아군색을 쓰면 봉인 조항 위반"** — 문언상 그렇다. 그래서 I8 로 **예외를 명문화**했고, 조건(캐릭터의 일부일 때만)을 붙였다. 별도 블루를 만들면 "파랑 = 우리 편" 규칙이 둘이 된다.
- **"컨셉 시트가 그림인데 왜 ADR 인가"** — 시트는 사라지거나 편집될 수 있다. 결정(D1~D8)과 불변식(I1~I8)은 여기 있어야 다음 에셋 작업이 해석 없이 따를 수 있다.
