# 0009. 부양 스웜 내비게이션 = 플레이어 중심 국소 3D 창 필드 (+2D 전역 유지)

- 상태: 채택
- 날짜: 2026-08-14
- 되돌리기 비용: 보통 (기존 2D 필드를 대체하지 않고 부양 이동 조회만 추가 — 3절 수정 ③)
- 대체: [0008](0008-hover-enemy-pursuit-reachability-modes.md) ← 이 문서가 0008의 Seek3D 모드 전환을 대체한다.
  0008의 토대였던 부양 v2 스프링·글라이드(3ccbd75e·4ce879fc)는 본 결정의 고도 수렴 실행기로 **존속**한다.

## 맥락

ADR 0008(도달성 기반 Seek3D) 구현을 PIE에 올리자 구조 결함 2개가 관측됐다(사용자 보고, 2026-08-14):

1. **전역 일제 상승** — 플로우 도달성은 플레이어에서 출발하는 BFS라, 플레이어가 도달 불가 단차에
   올라서는 순간 맵 전체의 플로우가 0이 된다 → 전 개체가 동시에 Seek3D로 들어가 스웜 전체가 한 판처럼
   상승. "막힌 개체만 국소적으로 떠오른다"는 의도와 달리 트리거가 전역 신호였다.
2. **점프 동조 출렁임** — Seek3D 목표 고도가 플레이어의 순간 Z에 묶여, 점프 한 번에 전 개체의 목표
   고도가 동시에 오르내린다.

사용자가 별도 검토 초안(부유체 스웜 내비게이션, 국소 3D 창 구조)을 제시했고, 본 문서는 그 초안을
3개 수정과 함께 채택한 기록이다. 응급 조치로 Seek3D는 `bEnableSeek3D=false` 기본 게이트로 잠갔다
(코드·판정 코어·테스트는 보존 — 정체 감지는 본 구조에서 재활용 여지).

## 목표와 비목표

- 목표:
  - 부양 스웜이 공중을 실제로 쓴다: 우회/타 넘기/터널 진입/단차 상승이 **국소적으로**(막힌 개체만) 나온다.
  - 플레이어 점프·낙하에 스웜 고도가 동조하지 않는다.
  - 구조적 엄폐 보존(0008 목표 승계 — 무제한 상공 사격 금지).
  - 4인 협동이 1급 전제다(스케일·병합 규칙 포함).
- 비목표:
  - 월드 전체를 덮는 3D 필드(전제 붕괴 — 4절).
  - 근접 적 재도입 없음(0008 승계).
  - 창 크기 런타임 리사이즈 경로(소유권 연기 — 초안 §9 유지).
- 규모 상한: 동시 200~300(캡 500) · 4인 · 이 경로 런타임 씬쿼리 추가 0(수정 ② 전역 베이크로 보장).

## 문제 분해 (초안 §2 — 채택의 핵심 근거)

| 구분 | 내용 | 성격 |
|---|---|---|
| 수평 위상 | 건물을 돌아갈 것인가 넘어갈 것인가 | 경로 탐색 문제 |
| 고도 결정 | 경로 위 각 지점에서 몇 미터에 뜰 것인가 | 필터/수렴 문제 |

관측 결함 2(점프 동조)는 경로 탐색 문제가 아니다 — 어떤 필드를 넣어도 목표 Z가 순간 Z에 묶이면
남는다. 따라서 필드 구조와 분리해 해결한다: **목표 Z = 플레이어의 마지막 접지 Z**, 고도 수렴 =
기존 부양 v2 스프링. (응급 패치에서 접지 Z 배관을 선반영.)

## 전제 전환 (초안 §4)

뱀파이어 서바이벌형 + 폐루프 디렉터의 **비가시 근거리 스폰**이면 실이동 거리는 20~40m다. 원래
요구했던 우회·터널 통과·단차 상승은 전부 플레이어 코앞 10~30m에서 벌어진다 — 원거리 경로 품질이
아니라 **근거리 품질 문제**이고, 예산을 좁은 범위에 몰아주는 것이 옳다. 이것이 A·B·C 공통 전제였던
"월드 전체 필드"를 깬다.

## 검토한 대안 (초안 §3 보존 + 이 세션의 안)

### 안 A — 컬럼당 고도 밴드 1개를 붙인 2D 플로우필드
기각(`치명`): 같은 XY에 통행 가능 고도가 둘 이상(터널 내부/터널 위 상공)인 맵을 표현 못 한다.
어느 값이 맞는지는 "읽는 개체가 지금 어디 있느냐"로 정해지므로 컬럼이 두 값을 다 들어야 한다.

### 안 B — 스팬(span) 기반 다층 전역 필드
보류: 구조적으로 유효하나 "월드 전체 필드" 전제가 무너졌다. 재검토 조건 = 전역 횡단이 게임
정체성이 되거나 국소 창이 실측 실패할 때.

### 안 C — 희소 복셀/옥트리 3D 필드
기각(`구조적`×2, 신뢰도 판단): LOD 경계 보간 불연속(300마리가 경계에서 튐) + 노드 홉 코스트 왜곡.
희소성의 채택 근거는 국소 창으로 범위를 줄이는 순간 소멸.

### 안 D — 도달성 기반 모드 전환 (ADR 0008, 직전 채택안)
PIE 관측으로 기각: 트리거(플로우 0)가 전역 신호라 국소 탈출기로 성립하지 않음(맥락 1). 정체 감지
트리거·순수 판정 코어는 유효한 부품으로 보존(게이트 오프 상태).

## 결정 — 채택 구조 (초안 §5 + 수정 3종)

1. **플레이어 중심 3D 국소 균일 그리드 창** (주 필드): 창 안에서만 3D 파면 전파. 겹침(터널
   위/아래)은 자료구조상 공짜, 균일 격자라 삼선형 보간 성립. 규모 예시(미검증): 셀 1.5m,
   96×96×32 ≈ 29만 셀 ≈ 2.4MB.
2. **기존 2D 표면 필드 = 전역 백업 + 비이동 소비자 전담** (**수정 ③ — "대체"가 아니라 "추가"**):
   현 2D 필드는 이동 외 하중(데미지 연결성 `CanAffectTarget`, 프론트 거리 게이트, 스폰 검증,
   서브리전 스트리밍·도어 스탬핑)을 지고 있다 — 전부 유지. 창 밖 개체와 지상형은 지금 그대로
   2D를 읽는다. 초안 §5.2의 "저해상도 2D 전역"은 신규 제작이 아니라 **이 기존 필드**다(디렉터
   스폰 검증 재사용 이득도 이미 실재).
3. **점유 획득 = 정적 지오메트리 전역 3D 복셀 오프라인 베이크** (**수정 ②**): 이동하는 창이 매번
   씬쿼리로 점유를 채우면 그것이 최대 비용이 된다. 정적 점유는 2D 표면 베이크와 같은 시점에 전역
   비트필드로 굽고(1.5m 해상도 맵 전체 수백 KB급), 창은 **계산 범위만** 담당한다. 문(파괴물)은
   현행 도어 스탬핑 방식으로 복셀에 덧찍는다. → 런타임 씬쿼리 0 유지.
4. **4인 협동 규칙** (**수정 ① — 초안의 치명 공백**): 창은 **플레이어당 1개(최대 4)**.
   - 적은 자기 타깃(현행 BestPlayer 선정)의 창을 읽는다 — 창 간 병합·중재 없음(겹쳐도 독립).
   - 갱신은 창 라운드로빈 스태거(불변식 5 "낡아도 안전"이 이를 허용한다).
   - 인원수별 창 축소는 데이터(4인 시 셀·창 축소로 총예산 상수화). 실측(첫 슬라이스)이 값을 정한다.
5. **단일 조회 이음매** (초안 §5.3): `QueryFlow(WorldPos) → {Direction, TargetZ, ZMin/ZMax, bValid}`.
   에이전트는 복셀·스팬·창·2D폴백을 모른다. **구현 첫 수 = 이 이음매를 현행 구조(2D 필드 + 부양
   v2 + 접지 Z) 위에 먼저 깔기** — 내부 교체가 국소 수정이 되게.
6. **고도 실행기 = 부양 v2 스프링·글라이드 그대로** (0008에서 존속): 필드는 방향과 통행 가능
   구간만 주고(불변식 4), 최종 위치는 로컬 스티어링(분리·스프링)이 정한다.

## 불변식

1. 필드는 목표당 공유 자원. 에이전트별 경로 탐색 없음, 조회 O(1).
2. 쓰기 주체는 필드 갱신 작업뿐 — 에이전트·디렉터는 읽기 전용.
3. 목표 판정은 플레이어의 **접지 Z**. 순간 Z를 쓰지 않는다.
4. 필드는 방향·통행 가능 고도 구간만 준다. 최종 위치는 로컬 스티어링(스프링·분리)이 정한다.
5. 낡은 필드로 동작해도 안전하다. 갱신 지연(스태거 포함)은 예외가 아니라 정상 상태다.
6. 에이전트는 어느 필드(3D 창/2D 전역)를 읽는지 모른다 — 조회 이음매 하나만 안다.
7. 씬쿼리는 **에이전트 수에 비례하지 않는다**(per-agent 0). 필드 갱신 주체의 유계·암ortize 쿼리
   (동적 장애물 재복셀화 등)는 허용하되 예산 항목으로 계측한다. 창 이동을 따라가는 슬래브 채우기는
   금지 — 그 경로가 최대 비용이 된다. *(정정 2026-08-15, 사용자 반론 수용: 원문 "런타임 씬쿼리 추가 0
   절대화"는 제1원리의 실체 — "적 수 비례 금지" — 보다 과하게 좁았다. 전역 정적 베이크는 여전히 기본값.)*
8. 4인이 1급: 어떤 예산·규칙도 "플레이어 1명" 가정으로 세우지 않는다(창 수 ≤ 4 전제로 검증).

## 실패 흐름 (초안 §8 보존)

창 밖으로 밀려난 개체 → 2D 전역(기존 필드)으로 전환. 파생 문제 2개와 처리:
- **재진입 층 오배치**: 재진입 순간 현재 Z가 자유 복셀인지 검사, 아니면 수직 최근접 자유 복셀로 스냅.
- **경계 진동**: 나갈 때/들어올 때 임계 분리(히스테리시스) + 전환 시 방향 몇 프레임 블렌드.

  층 편향 필드 다중화는 성능 예산 확인 후.

## 전환 조건

- 실이동 거리가 창을 넘고 창 밖 낌이 눈에 띈다 → 안 B(스팬 다층 전역) 복귀.
- 국소 창으로 못 담는 수직 개활 체적에서 3D 경로 선택이 게임플레이를 가른다 → 안 C 재검토.
- 실측에서 3D 창 갱신이 프레임 예산 초과 → 셀·창 축소, 그래도 안 되면 시야 방향 비대칭 창.
- 4인 창 4개가 예산을 깬다 → 인원수별 축소 데이터 강화 또는 타깃 클러스터당 공유 창 재설계.
- 디렉터가 창 크기 런타임 변경을 요구 → 창 크기 소유권 재결정.

## 검증 시나리오

- 정상 흐름: 플레이어가 단차 위 → **근처의 막힌 개체만** 창 필드가 위로 파면을 열어 국소 상승,
  멀리서 이동 중인 개체는 지형 상대 고도 유지(0008 결함 1의 부정 — 판정 기준).
- 실패 흐름: 플레이어 점프 연타 → 접지 Z 불변(불변식 3) → 스웜 고도 무반응(0008 결함 2의 부정).
- 실패 흐름(창 이탈): 급후퇴로 개체가 창 밖 → 2D 폴백 직진 → 재진입 시 자유 복셀 스냅, 경계 왕복 없음.

## 논의 중 제기된 반론

- "초안은 멀티플레이가 없다"(`치명`, 이 세션) → 수정 ①(플레이어당 창 + 타깃 기반 읽기 + 스태거 +
  인원수별 축소)로 해소. 실측 검증은 첫 슬라이스.
- "이동 창의 점유 획득이 최대 비용이 된다"(`구조적`, 이 세션) → 수정 ②(전역 정적 베이크)로 해소.
- "기존 2D 필드의 비이동 하중" (`구조적`, 이 세션) → 수정 ③(추가 방식)으로 해소, 되돌리기 비용도
  완화.
