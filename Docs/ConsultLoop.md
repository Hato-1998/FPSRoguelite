# ConsultLoop — Codex 협업 프로토콜 (안건 = Claude / 적대 레드팀 = Codex)

> **§0·§0-1·§1 = Codex 호출 전반의 공통 정책**(아래 3채널 전부에 적용). **§2~ = 토론 루프(`/consult`) 전용.**
> 사용자가 *"`ConsultLoop.md` 읽고 `<주제>` 토론 결과 줘"* 또는 `/consult <주제>` 라고 하면, Claude는 이 문서의 절차대로 자신이 낸 **안건**을 Codex **적대 레드팀**에게 공격받아 수렴시킨 뒤 결과를 보고한다.
> 작업 시작 전 `Game.md`(SSOT 허브)·PM 보드(`Workflow.md` §6-9)·주제 관련 `Docs/SSOT/*.md`를 먼저 본다(허브 §0-1 라우팅).

---

## §0. 목적 · 위치 (무엇이며, 무엇이 아닌가)

프로젝트 결정을 **내부 시야만으로 굳히지 않기 위한** 외부 적대 검증 채널이다. Claude는 이 게임의 전제(제1원리·성능예산·서버권위)를 공유하고 있어 자기 안건의 사각을 스스로 보기 어렵다. Codex는 그 전제를 공유하지 않는 **외부인**으로서 안건을 무너뜨리려 읽는다.

기존 외부 AI 협업과 **역할이 다르다 — 제3 채널**:

| 채널 | 누가 | 트리거 | 용도 | 산출물 |
|---|---|---|---|---|
| **레드팀 리뷰 게이트** (`Workflow.md` §6-6-1) | **내부 Fable 서브에이전트** | 머지 직전(범위 IN일 때) | 코드 **diff 게이트**(P1/P2/P3) | 머지 커밋 / `Docs/Specs/` 하단 |
| `GameConfirm.md` | 외부 AI | 비정기 | **문서 리뷰**(외부가 작성) | 외부 |
| **ConsultLoop** (`Scripts/consult-codex.ps1`, `codex exec`) | **외부 Codex** | 사용자가 주제 지목 | 설계·구조 **라이브 적대 토론(컨설팅)** | `Docs/Review/` (**추적**, 프롬프트 매니저 인입원) |

→ ConsultLoop은 **자문(advisory)** 이다. 토론 자체로는 코드/에셋을 바꾸지 않는다(§6).

> **2026-08-07 전환**: 머지 게이트는 외부 Codex(`Scripts/codex-review.ps1`)에서 **내부 Fable 레드팀**으로 옮겼다(`codex review`에 적대 페르소나를 넣을 방법이 없다는 게 실증됨 + 사용량 한도·무응답). 그래서 **외부 모델 교차검증이 남은 곳은 이 토론 채널뿐**이다 — Codex를 여기서까지 빼면 이 프로젝트에 Claude 아닌 목소리가 0개가 된다.

## §0-1. 적대 검증 호출 적용 범위 게이트

> 도입 2026-08-07(사용자 결정). **위 표의 레드팀 리뷰 게이트와 Codex 토론 채널 양쪽에 적용된다.**

**적대 검증(내부 레드팀 · 외부 Codex)은 게임의 코어 · 리팩토링 · 설계/구조 사안에만 부른다.**

- **판정 기준 = [`Docs/SSOT/Workflow.md`](SSOT/Workflow.md) §6-5-2 (1)의 트리거 표 `T1~T5`를 그대로 쓴다.** 하나라도 걸리면 호출(IN).
  요약: `T1` 새 서브시스템·클래스 트리 신설 · `T2` 여러 클래스에 걸친 구조 변경/리팩토링 · `T3` 복제·수명주기·GAS·성능 경로가 얽힌 설계 · `T4` 확장 스키마 설계 · `T5` 코어 도메인 헤더 변경.
- 즉 **"§6-5-2 코어 갈래 = Codex 호출"로 한 몸**이다. 판정 기준을 여기서 따로 정의하지 않는다 — **같은 개념의 정의가 둘이면 반드시 드리프트한다.**
- **호출 안 함(OUT) 예시** — 콘텐츠·수치 튜닝(DataAsset 값·밸런스 ini·커브) / BP·UMG 배선 / 에셋 임포트·머티리얼·애니메이션 / 구조 무변경 국지 버그수정 / 오타·주석·문서 / 소소한 툴 개선.
  이런 브랜치는 §6-7 머지 검증에서 **레드팀 게이트를 건너뛰고** 빌드 + 헤드리스 스모크 + `git diff` 자기비판으로 끝낸다.
- **애매하면 호출한다** — §6-5-2의 "애매하면 코어로 올린다"와 같은 방향(얕게 검토해 재작업하는 비용 > 레드팀 1회).
- 사용자가 명시적으로 *"Codex에 물어봐"* · *"리뷰 걸어"* 라고 하면 범위와 무관하게 호출한다.

## §1. 역할 정의

| | **📋 안건 소유자 = Claude** | **🕸️ 웹/앱 적대 레드팀 = Codex** |
|---|---|---|
| 정체 | 이 프로젝트의 전제·제약을 공유하는 **내부자**. 코어 갈래면 Fable, 그 외면 Opus(`Workflow.md` §6-5) | 대규모 웹/앱을 설계·운영해 온 **외부인**. 이 게임의 사정을 공유하지 않는다 |
| 하는 일 | 안건(플랜·구조 제안·diff)을 쓰고, 공격을 판독해 **수용 / 기각 / 사용자결정**으로 분류하고, 토론을 끝낸다 | 안건을 옹호하지 않고 **무너뜨린다**. 라운드마다 공격 축 1개를 이름으로 선언하고 그 축의 반례만 낸다 |
| 권한 | **최종 결정권** — §3. 단 기각·종료는 **근거 기록이 있어야 성립** | 반례 공급. 설득·합의 도출은 역할이 아니다 |

- **Codex 프라이머 원문 = [`Docs/CodexRedTeamPersona.md`](CodexRedTeamPersona.md).** 권한 경계(단정 가능 영역 vs `[가설]` 태그 필수 영역)·근거 규칙·출력 계약이 전부 거기 있다. **여기 중복 서술하지 않는다.** 래퍼가 프롬프트 앞에 자동 prepend한다(§4).
- **머지 게이트의 레드팀은 이것과 다른 페르소나다** — 내부 Fable용 프라이머 = [`Docs/InternalRedTeamReview.md`](InternalRedTeamReview.md), 절차 = `Workflow.md` §6-6-1. 이쪽은 "외부인"이 아니라 **"설계 근거를 못 들은 리뷰어"** 로 독립성을 만든다(같은 Claude 모델이라 컨텍스트 차단이 유일한 독립 수단이다).
- **공통 구속** — 장르 정체성(`Game.md` §1, **Hero Shooter 아님**)·제1원리(적 수백을 싸게)는 양쪽 다 구속한다. 어느 쪽 제안이든 이걸 깨면 무효. Codex는 리포 `AGENTS.md`를 자동 로드해 이미 인지한다.
- **다른 렌즈가 필요해지면** `Docs/CodexRedTeamPersona.md`를 복제해 새 파일을 만들고 `-Persona <경로>`로 지정한다(스크립트 수정 불요).
  종전의 **클라이언트/콘텐츠 렌즈**(손맛·입력·UI·연출·콘텐츠 실현성)는 2026-08-07 자로 상시 운용에서 내렸다 — 손맛·연출 주제는 §0-1 기준 OUT이라 Codex를 부르지 않고 Claude 단독 자문으로 간다. 되살릴 땐 위 경로로.

## §2. 트리거

- 자연어: **"`ConsultLoop.md` 읽고 `<주제>` 토론 결과 줘"**
- 슬래시: **`/consult <주제>`** (`.claude/commands/consult.md`)
- **주제를 받으면 §0-1 범위 게이트를 먼저 판정한다.** OUT이면 Codex를 부르지 않고 Claude 단독 자문으로 진행하며, 그 사실을 보고에 1줄로 밝힌다(조용히 생략 금지).
- IN 주제 예: "스폰 디렉터 복제 모델", "카드 모디파이어 적용 순서", "무기 파츠 스키마 계층".
- 사용자가 *"시간이 얼마나 걸리든"* 이라 했으면 **수렴까지** 돈다(§3). 라운드 수 하드 캡 없음.

## §3. 토론 프로토콜 (수렴 기반)

**R0 — 범위 설정 (Claude 단독, 호출 전):**
1. §0-1 게이트 판정(IN/OUT).
2. 주제 관련 `Docs/SSOT/*.md` + 관련 소스/콘텐츠를 읽어 **사실 기반**을 잡는다(추측 금지).
3. 의제를 2~4개 핵심 쟁점으로 프레이밍한다.

**R1 — 안건 제시:**
1. Claude가 **안건**을 작성(쟁점별 구조 제안 + 리스크/예산).
2. 그 안건 + 의제 + 구체 질문을 프롬프트 파일에 적고 → `Scripts/consult-codex.ps1 -PromptFile <file>` 로 **레드팀의 공격**을 받는다(§4).

**R2+ — 교차 반론 (반복):**
1. Claude가 Codex 출력을 **판독**(수용/기각/사용자결정 구분). 장르·예산 위반 주장은 §1 근거로 반박.
2. 조정된 안건 + 남은 질문을 다시 보내 다음 공격을 받는다.
3. **새로운 실질 논점이 더 안 나오면 수렴**으로 보고 종료(통상 3~6라운드, 단순 주제는 1~2, 복잡하면 더).

**수렴 정리 — 세 갈래로 분류:**
- **(a) 합의** — 안건에 반영한 권고.
- **(b) 미해결 쟁점** — trade-off가 남아 결정 못 한 것(양측 근거 병기).
- **(c) 사용자 결정 필요** — 취향·범위·우선순위 등 사람이 정해야 하는 것.

### §3-1. 종료 — 최종 결정권은 안건 소유자(Claude)에게 있다

Claude는 라운드 규칙과 무관하게 **언제든 종료를 선언할 수 있다.** 대신 종료가 성립하려면 **아래 둘 다** 남겨야 한다.

1. **종료 사유 1줄** — `수렴` / `축 소진` / `안건 밖` / `제1원리·엔진 제약상 무효` / `비용 대비 무의미` 중 하나 + 한 문장.
2. **🧾 기각 원장** — 기각한 Codex 지적을 **하나도 빠짐없이** 적고 각각에 기각 근거를 붙인다. 근거로 인정되는 것은 셋뿐:
   - 제1원리·장르 정체성 조항(`Game.md` §1 / `AGENTS.md` 핵심 4원칙)
   - 이 리포의 코드·문서 인용(경로 표기)
   - 실측치 · 빌드/스모크 결과

> **"동의하지 않는다" · "우선순위가 아니다"만으로는 기각할 수 없다.** 근거를 못 대면 그 지적은 기각이 아니라 **(b) 미해결 쟁점**으로 남긴다. 결정권은 토론을 끝낼 권한이지, 불편한 지적을 지울 권한이 아니다.

> `[가설]` 태그가 붙은 지적은 **기각이 아니라 검증 항목**으로 옮긴다. 엔진 특이사항(복제·GAS·틱/GC)은 Codex 권한 밖이라 그렇게 표기된 것이지 틀렸다는 뜻이 아니다 — 확인 없이 버리지 말 것.

## §4. Codex 호출법

```powershell
# 한 라운드: 안건 파일 작성 → 호출 (역할 프라이머는 래퍼가 자동으로 앞에 붙인다)
Scripts\consult-codex.ps1 -PromptFile <round.txt> -Title <주제슬러그>
# 다른 렌즈로: -Persona Docs\<렌즈파일>.md   ·   프라이머 없이: -NoPersona
# 빠른 단발/검증:
Scripts\consult-codex.ps1 -Prompt "<짧은 질문>" -DryRun   # 호출 없이 조립된 프롬프트만 확인
```

- 래퍼가 `codex -C <repo> exec -s read-only -` (read-only 샌드박스, 프롬프트 stdin)로 호출. Codex가 `AGENTS.md`+리포를 읽어 답한다.
- **안건 파일 구조** (Claude가 매 라운드 작성 — **역할 프라이머는 쓰지 않는다.** 래퍼가 붙인다):
  1. *주제 + 현재까지의 의제/합의/쟁점 요약*
  2. *이번 라운드 안건*
  3. *Codex에게 묻는 구체 질문 2~4개* (열린 토론이 아니라 **쟁점에 답하게**)
- ⚠️ **`codex review`(diff 리뷰 서브커맨드)를 되살릴 생각이면 먼저 알 것**: scope 플래그와 커스텀 프롬프트를 **동시에 못 받는다**(`--help`는 `[PROMPT]`를 표시하지만 실제론 `error: the argument '--base <BRANCH>' cannot be used with '[PROMPT]'` — 3개 플래그 전부, v0.130.0-alpha.5 실측). 즉 **적대 페르소나를 넣을 수 없다.** 이게 머지 게이트를 내부 Fable로 옮긴 이유다(§0, `Workflow.md` §6-6-1).
- **5분 워치독** — 출력이 5분 내 없으면 프로세스를 종료하고 토론을 스킵한 뒤 진행한다(사용자 지침 2026-06-15).
- Codex 미설치/미인증이면 래퍼가 안내 후 멈춘다 → `npm install -g @openai/codex`; `codex login` 1회.
- codex 경로 강제: `$env:CODEX_EXE = '<경로>'`.

## §5. 산출물 포맷

`Docs/Review/<yyyyMMdd>-<주제슬러그>.md` 에 저장(**추적** — 설계 의사결정 기록 + 프롬프트 매니저 인입원):

```markdown
# 컨설트: <주제> (<날짜>)

## 범위 / 읽은 컨텍스트      ← 어떤 SSOT/소스를 근거로 했나 + §0-1 판정(IN/OUT)
## 📋 안건 (Claude)
## 🕸️ 레드팀 핵심 공격 (Codex)
## 토론 로그 요약           ← 라운드별 핵심 교환 (장황한 원문 X)
## ✅ 합의 권고
## 🧾 기각 원장             ← 기각한 지적 전부 + 각각의 근거(제1원리 조항 / 코드 인용 / 실측치)
## ⚖️ 미해결 쟁점           ← trade-off + 양측 근거
## 🙋 사용자 결정 필요
## 📌 액션 아이템           ← 갱신할 Docs/SSOT 파일 / 반영할 로드맵 유닛
```

- 사용자에겐 채팅으로 **압축 요약**(합의/기각/쟁점/결정필요/액션)을 보고하고, 전체는 위 파일을 가리킨다.
- **프롬프트 매니저 인입**: 리포트 저장 후 `📌 액션 아이템`을 `Docs/TaskPrompts_Master.md` §E 인입 표에 한 줄로 등재(주제·리포트 링크·대상 유닛).
- 원시 Codex 응답은 `Docs/Review/_raw/`에 타임스탬프로 남는다(gitignore, 감사용).
- 2026-08-07 이전 리포트는 옛 역할 배치(백엔드 렌즈 × 클라이언트 렌즈)로 작성됐다. **사료이므로 소급 개정하지 않는다.**

## §6. 가드레일

1. **범위 게이트 우선(§0-1)** — 호출 전에 IN/OUT부터 판정한다. OUT인데 부르지 않는다, IN인데 조용히 건너뛰지 않는다.
2. **자문 전용** — 토론은 코드/에셋을 바꾸지 않는다. 채택된 설계는 **별도 단계**에서 해당 `Docs/SSOT/` 도메인 파일을 먼저 갱신(원칙3) 후 구현.
3. **사실 기반** — R0에서 실제 SSOT/소스를 읽는다. 양쪽 다 추측으로 단정 금지(엔진 API는 소스 대조).
4. **장르·제1원리 우선(§1)** — 어느 쪽 제안이든 §1 구속을 깨면 무효. 비자명한 구조 결론은 ①제1원리 ②엔진 기본값·기존 인프라와의 관계 ③프로젝트 제약 정합 3줄로 명시.
5. **수렴이 목표, 합의 강요 아님** — 안 좁혀지는 trade-off는 **(b)쟁점/(c)사용자결정**으로 정직하게 남긴다. 억지 단일 결론 금지.
6. **최종 결정권 = 안건 소유자(Claude)** — 단 §3-1의 **종료 사유 + 기각 원장**을 남겨야 성립한다. 근거 없는 기각은 기각이 아니다.
7. **사용자 승인 게이트는 불변** — Claude의 결정권은 **토론을 끝내고 안건을 확정하는 권한**이지 실행 권한이 아니다. HIGH_RISK(파일 변경·빌드·커밋)와 채택 설계의 SSOT 반영은 여전히 사용자 승인 뒤에 한다.
8. **read-only** — Codex는 read-only 샌드박스로 호출(단, Windows `codex review`는 workspace-write로 동작 — 신뢰 로컬 리포 전용).
