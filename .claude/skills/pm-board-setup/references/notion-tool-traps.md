# 노션 도구 함정 — 설치·운영 중 밟은 것들

이 문서는 설치기(`SKILL.md`)와 설치된 프로젝트 양쪽이 참조한다.

> 등록 2026-09-09 (노션 워크스페이스 재편 세션에서 전부 실제로 밟은 것). 구조·역할 분담 = `{{PROTOCOL_DOC}}` (9).

## K1. 노션에 쓴 한글이 조용히 다른 글자로 바뀐다

**증상** — 저장은 성공하고 응답도 정상인데, 나중에 읽어 보면 낱말 하나가 다르다.
실측된 변조: `비쌈`→`비쌀` · `바이탈`→`바이털` · `읽힌다`→`읽힐다` · `오락실`→`오락기실` · `그리는`→`그러는` · `쿨다운`→`쿼타임` · `정답`→`오른답` · `낡는다`→`낙아진다`.

**원인** — 도구 인자를 `\uXXXX` 이스케이프로 직렬화하면 그 변환 과정에서 글자가 바뀐다. **도구가 아니라 호출 경로의 문제**라 도구를 바꿔도 안 낫는다.

**처방**
1. 인자에 **한글을 리터럴로** 쓴다(`\uXXXX` 금지).
2. **쓴 뒤 반드시 `notion-fetch` 로 되읽어 확인한다.** 이것 말고 잡을 방법이 없다.
3. 🚨 **고친 뒤에도 되읽는다.** 교정 문자열도 같은 경로로 나가므로 **교정이 또 틀릴 수 있다** — 실제로 `낡`(U+B0A1) 을 고치려다 `낙`(U+B099) 을 두 번 연속 보냈다. 호출이 성공했다는 응답은 *매칭에 성공했다*는 뜻이지 *올바른 글자가 들어갔다*는 뜻이 아니다. 한 글자짜리 교정은 **코드포인트를 확인하고** 보낼 것.

⚠️ **문법이 깨진 낱말(`읽힐다`·`쿼타임`)은 눈에 띄지만 말이 되는 낱말로 바뀌면 못 잡는다.** 그래서 첫 청크를 짧게 쓰고 본문은 `insert_content` 로 이어붙이는 편이 안전하다 — 실측상 **오염은 `notion-create-pages` 의 첫 덩어리에 몰린다.**

## K2. 페이지를 고쳤을 뿐인데 자식 페이지가 사라졌다

**원인** — `allow_deleting_content: true` 는 **새 본문에서 참조되지 않는 자식 페이지·DB 를 삭제한다.** 그런데 **마크다운 링크는 참조로 세지 않는다** — `<page url="...">` 태그만 센다.

**처방** — 자식 페이지가 있는 페이지에는 쓰지 않는다. 인라인 뷰만 지워야 하면 `update_content` 로 **그 블록만** 지운다(그때 에러 메시지가 삭제 대상을 먼저 알려주므로 자식이 안전한지 확인할 수 있다).

⚠️ **`notion-fetch` 가 성공한다고 페이지가 살아 있는 게 아니다** — 삭제된 페이지도 본문을 정상 반환하고 헤더에만 `deleted` 가 붙는다. 편집하려 하면 `Can't edit block that is archived`.

## K3. `update_content` 가 통째로 반려된다

**원인** — 배치가 **원자적**이다. 한 항목이라도 매칭 실패하면 전체가 취소된다.

**처방** — 에러가 실패한 항목을 알려주니 빼고 재시도. ⚠️ **검색 문자열도 K1 의 오염을 탄다** — 실제로 `잰`→`재` 로 깨진 old_str 때문에 배치 전체가 반려됐다. 매칭이 안 되면 내용을 의심하기 전에 **보낸 문자열부터** 의심할 것.

## K4. 큰 본문으로 페이지를 만들면 JSON 파싱이 깨진다

**원인** — 인자가 길면 직렬화가 실패한다. 11KB 에서도 실패한 사례가 있다.

**처방** — **호출당 12KB 이하**로 쪼갠다. 페이지를 작게 만들고 `insert_content`(`position=end`)로 이어붙인다. 실패하면 내용을 의심하지 말고 **더 잘게 쪼갤 것.**

## K5. 이모지를 기호로 바꾸는데 절반이 "매칭 없음"이 난다

**원인** — 같은 DB 안에서도 페이지마다 형식이 다르다. 결정 기록은 일부가 **콜아웃 블록**(`<callout icon="⚖️">`), 일부가 **인용문**(`> ⚖️ ...`)이었다.

**처방** — `icon="..."` 속성을 치지 말고 **문자 자체를 `replace_all_matches` 로** 친다. 두 형식이 한 번에 덮인다.

⚠️ **repo 원문 스캔만으로 목록을 만들면 놓친다** — 노션에만 있는 합성 요약절에 다른 이모지가 있다(`🔴` 대체됨 안내). 별도 스윕이 필요하다.

⚠️ **도형기호를 이모지로 오인하지 말 것** — 화살표(`→ ← ↑ ↓ ↔`) · 박스드로잉(`═ ─ │ ┌ ┐`) · 원문자(`① ② ③`) · 삼각형(`▲ ▼ ◀ ►`)은 **기호**이므로 남긴다.

## K6. 보드 "전수 조회" 가 조용히 잘려 진행중 행을 놓친다

**증상** — 세션 시작 보드 조회는 성공하고 행도 잔뜩 나오는데, 다른 세션이 진행중인 작업이 목록에 없다. 그래서 같은 파일을 동시에 건드린다.

**원인** — `notion-query-data-sources` SQL 이 **100행에서 잘린다.** 응답의 `has_more: true` 가 유일한 신호인데 프로토콜이 그 필드를 한 번도 확인하지 않았다. `ORDER BY` 도 없어서 **어느 행이 잘려 나가는지 정해져 있지도 않다.**

**실측**(2026-09-09, `df2f6601`) — 활성 114행(대기 108·결정대기 4·진행중 2) 중 100행만 반환. 잘린 꼬리에 **진행중 2건 중 1건**이 있었고, 그 행의 `주요경로`(`Content/UI/HUD/`)에 해당하는 미커밋 파일이 그 시각 작업 트리에 있었다 — 병렬 충돌 검사가 뚫린 채로 돌고 있었다.

**해결** — 둘 중 하나. 정본 = `{{PROTOCOL_DOC}}` (2).
1. **가져오는 양을 줄인다**(채택) — 세션 시작에는 작업집합만: `WHERE "상태" IN ('진행중','차단') OR "우선순위"='크리티컬'`. 실측 2행. 판정 기준 = **조회 비용은 활성 행 수와 무관해야 한다.**
2. **끝까지 받는다** — 보드 전체를 훑어야 하는 작업(백필·감사·DAG 유지)은 `LIMIT/OFFSET` 으로 `has_more` 가 `false` 가 될 때까지 페이지네이션한다(동작 확인함).

⚠️ **이건 성능 문제로 위장한 정합성 문제다.** 느려진 게 아니라 **설계 전제가 데이터 증가에 깨진 것**이다 — 프로토콜이 짜인 시점 활성 17건이 114건(6.7배)이 됐다. 조회를 새로 추가할 때마다 "활성 행이 10배가 되어도 이 조회가 커지지 않는가" 를 물어라.

## H9. PowerShell 로 REST 를 부르면 한글 필드가 `?` 로 도착한다

**증상** — 스크립트는 정상 종료하는데 API 가 "그런 속성 없음" 으로 떨어진다. 로컬 코드에서는 한글이 멀쩡해 보이고, `ConvertTo-Json` 출력도 콘솔에서 정상이다.

**원인** — `Invoke-WebRequest`/`Invoke-RestMethod` 에 `-Body` 로 **문자열**을 주면 PS 5.1 이 비-ASCII 를 `?`(0x3F)로 바꿔 보낸다. JSON 은 문법상 멀쩡해서 서버는 400 을 주고, 로컬에는 아무 흔적이 없다.

**실측**(2026-09-09, `df2f6601`) — 로컬 `HttpListener` 로 실제 바이트를 받아 확인:

| 보낸 방식 | 도착한 것 | 크기 |
|---|---|---|
| `-Body $json` (문자열) | `{"property":"??","select":{"equals":"???"}}` | 79 B |
| `-Body ([Text.Encoding]::UTF8.GetBytes($json))` | `{"property":"상태","select":{"equals":"진행중"}}` | 89 B |
| `-ContentType 'application/json; charset=utf-8'` | 위와 동일(온전) | 89 B |

**해결** — 바디를 **UTF-8 바이트 배열**로 넘긴다. 실패가 조용해서 `charset` 도 같이 명시한다(둘 중 하나로도 고쳐진다).

```powershell
$bodyBytes = [System.Text.Encoding]::UTF8.GetBytes($bodyJson)
Invoke-WebRequest -Uri $u -Method Post -Body $bodyBytes -ContentType 'application/json; charset=utf-8' -UseBasicParsing
```

⚠️ **같은 호출의 `ConvertTo-Json` 에는 `-Depth` 를 넉넉히 준다**(기본값 2). 중첩 해시테이블이 조용히 `"System.Collections.Hashtable"` 문자열로 뭉개진다 — 실측 대조군으로 재현됨.

🚨 **토큰이 없어 API 를 못 부르는 상태에서는 이 버그가 안 잡힌다.** 구문·BOM·무토큰 분기가 전부 통과해도 실제 호출은 100% 실패한다. 검증 수단이 없으면 **로컬 `HttpListener` 로 모의 서버를 띄워 바이트를 받아 보라** — 이 항목이 그렇게 잡혔다.
