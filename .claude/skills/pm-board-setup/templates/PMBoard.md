# PM 보드(Notion) 프로토콜 — 작업 추적의 SSOT

> 도입 {{DATE}}. **모든 세션·클론의 작업 상태·우선순위·선행관계는 Notion "작업 보드"가 단일 진실**이다.
> 근거(제1원리): git 문서는 브랜치-로컬이라 머지 전엔 병렬 세션끼리 서로 안 보인다 — 공유 가변 상태는 git 밖에 산다.
> 이 문서가 규칙 원문이다. `.claude/agents/pm-board.md`·`.claude/commands/board.md`·Notion "운영 규칙" 페이지는 이 문서를 따르며, 어긋나면 이 문서가 옳다.

## (1) 하드 게이트 (필수)
- **작업 전 보드 클레임 없이 프로젝트 작업 착수 금지.** Notion MCP 미연결 세션은 코드/콘텐츠/문서 작업을 시작하지 말고 **사용자에게 연결을 요청 후 대기**한다.
- **유일한 예외** = 사용자가 그 세션에서 명시적으로 "보드 없이 진행"을 지시한 경우(Notion 장애 포함 — 우회 권한은 사용자에게만 있다).
- **적용 대상** = 커밋을 낳는 작업 단위. 읽기 전용 조회·질답·한 줄 수정은 제외.

## (2) 보드 위치·도구 레시피
| 항목 | 값 |
|---|---|
| 허브 페이지 | `{{HUB_URL}}` ({{PROJECT}} PM 보드) |
| DB "작업 보드" | `{{TASKS_DB_URL}}` |
| 데이터소스 | `{{TASKS_DS}}` |

- **전수 조회**(세션 시작 1회): `notion-query-data-sources` SQL —
  `SELECT "작업명","상태","우선순위","크기",<!-- IF:MILESTONE -->"마일스톤",<!-- /IF:MILESTONE --><!-- IF:GATE -->"{{GATE_COL}}",<!-- /IF:GATE -->"담당","브랜치","선행작업","주요경로",url FROM "{{TASKS_DS}}" WHERE "상태" IN ('진행중','대기','차단','결정대기')`
  - ⚠️ **이 도구는 무료 플랜 호출 한도가 있다 — 세션당 1~2회로 절약**(시작 1회 + 필요 시 마감 1회).
  - 🔒 **`검증중`을 뺀 것은 의도다.** `검증중` = **사람이 직접 확인해야 끝나는 것**이라 에이전트가 집을 작업이 아니고, 넣으면 세션 시작 목록만 길어진다. 이 행들은 사용자가 보드를 직접 열어서 본다. `보류`·`완료`·`폐기`도 같은 이유로 제외(완료는 아카이브 뷰).
  - ⚠️ 단 **보드 전체를 훑는 작업**(스키마 백필 등)에서는 이 SQL을 기준으로 삼지 말 것 — 목적에 맞게 `상태` 필터를 다시 짜라.

- **표적 조회**(무제한): `notion-search`에 `data_source_url` 지정. **행 내용 읽기**(무제한): `notion-fetch`(행 페이지 URL). ⚠️ DB URL을 fetch하면 스키마·뷰만 나오고 행은 안 나온다.

## (3) 작업 전 절차 (클레임)
1. **보드 조회**(위 SQL 1회) — 진행중 전체 + 대기·차단·결정대기.
2. **크리티컬 확인** — 미착수 크리티컬이 있으면 지금 요청과 무관해도 사용자에게 먼저 보고.
3. **행 확보** — 내 작업이 보드에 없으면 생성(상태=대기, 우선순위는 (5)로 판단, 출처=사용자지시/에이전트발견, `크기`<!-- IF:MILESTONE -->·`마일스톤`<!-- /IF:MILESTONE --><!-- IF:GATE -->·`{{GATE_COL}}`<!-- /IF:GATE --> 기입).
4. **선행 확인** — `선행작업`이 미완료(완료 아님)면 착수 금지. 다른 작업을 고르거나 사용자에게 보고.
<!-- IF:MILESTONE -->
   - **마일스톤 순서 확인**((8) 개시 규칙) — 이 행의 `마일스톤`보다 앞선 마일스톤에 활성 행이 남아 있으면 기본값은 **그쪽 먼저**다. 당겨 쓰려면 예외 3가지 중 하나에 해당해야 하고 사유를 로그에 남긴다.
<!-- /IF:MILESTONE -->
5. **병렬 충돌 검사** — 진행중 행들과 `주요경로`/`영역`이 겹치면 착수 전 사용자에게 보고(기본값 = 겹치면 대기).
6. **클레임** — 상태=진행중, `담당`=`<클론폴더>@<브랜치> · MMDD-키워드`, `브랜치` 기입(트렁크 기반이면 `main`).
7. **경합 확인** — 클레임 직후 행을 재조회해 `담당`이 나인지 확인(Notion엔 트랜잭션이 없다). 다른 세션이면 양보하고 1로.

## (4) 작업 후 / 중단 시 절차
1. **상태 갱신** — 완료(검증 통과, `완료커밋`에 해시) / 검증중(사람 확인 대기) / 차단(사유를 로그에) / **폐기**(트랙을 접었거나 대상이 사라짐 — 기준은 (5)) / 핸드오프면 진행중 유지 + `담당` 비우고 재개 메모.
2. **로그 append** — 행 페이지에 1~3줄: 결과·커밋 해시·다음 단계. 인계 컨텍스트(검증법·함정·미커밋 산출물)도 행 페이지 본문에.
3. **파생 등록** — 작업 중 발견한 개선점=백로그, 실행 영향 있는 문제=하이/미듐/로우로 신규 행.
4. **후행 차단 해제** — 내 완료로 선행이 풀린 행이 있는지 확인.<!-- IF:MILESTONE --> **내 완료로 그 마일스톤의 활성 행이 0이 되면 사용자에게 보고**((8) 상태 갱신 트리거).<!-- /IF:MILESTONE -->
5. 완료 상세 경위는 프로젝트의 워크로그 문서 맨 위로(증상→해결은 트러블슈팅 문서).

## (5) 우선순위 규칙 (5단계)
| 등급 | 의미 | 부여 주체 |
|---|---|---|
| **크리티컬** | 사용자가 지시하는 긴급사항 — 존재 시 무조건 최우선 착수 | **사용자 전용** (에이전트 부여·강등 금지) |
| **하이** | 현재 트랙을 막거나 실행/검증을 막는 것 | 담당 에이전트 판단 |
| **미듐** | 현재 트랙 범위 내 일반 작업 | 담당 에이전트 판단 |
| **로우** | 범위 밖이거나 급하지 않음 | 담당 에이전트 판단 |
| **백로그** | 실행상 문제 없으나 개선할 점(리팩토링 후보·문서 드리프트 등) | 누구나 등록 |

- 승격/강등은 사용자(PM) 권한 — 에이전트는 로그에 제안만 남긴다.
- 상태 축: 대기 / 진행중 / 검증중 / **결정대기**(사용자 결정 필요 — PM 인박스 뷰) / 차단 / 보류 / 완료 / **폐기**.
- **완료 vs 폐기**
  - **완료** = 이 행이 맡은 일을 **실제로 해냈다**. `완료커밋`에 해시. 범위 조정으로 남은 일을 신규 행으로 뺀 경우도 **완료**. 조사만 하고 "문제 없음"으로 닫은 것도 **완료**(결론을 냈다).
  - **폐기** = **산출물 없이 트랙을 접었거나**, 대상이 사라져 **할 수 없게 됐다**. `완료커밋`은 비우거나 `폐기(사유 요약)`.
  - 폐기 시 **사유를 행 본문에 반드시** 남긴다(왜 접었는지 + 되살리려면 무엇이 필요한지).
  - **되살릴 땐 그 행을 재사용하지 말고 신규 행**으로 연다 — 접힌 뒤 코드가 달라져 스펙을 다시 써야 한다.
- **`크기`**(select `S`/`M`/`L`/`XL`) — **상대크기이며 달력 기간이 아니다.** `S`=1세션 · `M`=2~3세션 · `L`=4세션 이상 · `XL`=크기를 못 재겠거나 4세션으로도 안 끝난다 = **쪼개야 한다**.
  - 🔒 **`XL` 행은 클레임하지 않는다** — 착수 전에 `S`~`L` 행들로 **분할한 뒤** 착수한다(원 행은 상위 묶음으로 남기거나 폐기). 분할 없이 집으면 완료 판정이 불가능해진다.

## (6) 운영 규칙
- **완료·폐기 행은 보드에 남긴다**(아카이브 뷰) — 활성 조회 SQL이 둘 다 제외하므로 비용 증가 없음. 폐기 행을 지우면 "왜 안 했는지"가 사라져 같은 걸 다시 착수하게 된다.
- `PROGRESS.md`는 포인터 전용 — 작업 내용을 다시 적지 않는다(이중 SSOT 금지). SessionStart 훅이 이 포인터를 매 세션 출력해 게이트를 상기시킨다.
- MCP 설정은 repo `.mcp.json`으로 전파(시크릿 없음 — OAuth는 사용자 레벨). 새 클론 첫 사용 시 승인 1회.
- **상시 감시(크론 폴링)는 미채택.** 보드를 세션 시작에 1회, 커밋 전에 1회 무조건 부르므로 폴링이 더해 주는 것이 거의 없다. 사용자가 Notion에 넣은 크리티컬은 다음 세션 시작 조회에서 집힌다.

## (7) 실행 주체 — `pm-board` 에이전트 / `/board`
> 근거(제1원리): 클레임 7단계 + 마감 5단계를 매 세션 메인 에이전트가 직접 밟으면 ①절차가 길어 빠뜨리고 ②조회 덤프가 메인 컨텍스트를 먹고 ③SQL 한도를 관리하는 주체가 없다. 절차를 고정된 단일 창구에 몰면 셋 다 해결된다.

- **호출** = `/board [클레임 <작업> | 마감 <결과·커밋> | 감사]`(인자 없으면 현황). 커밋을 낳는 작업에 착수하기 전 `/board 클레임`이 (1) 하드 게이트를 밟는 정규 경로다.
- **정의** = `.claude/agents/pm-board.md`(에이전트) · `.claude/commands/board.md`(슬래시). 둘 다 git 추적 대상이다.
- **에이전트는 절차를 복제해 갖고 있지 않다** — 이 문서를 읽고 따른다. 프로토콜이 바뀌면 여기만 고치면 된다.

**권한 경계 — 에이전트는 "추가"만 한다**

| | |
|---|---|
| ✅ 할 수 있다 | 읽기 전부 · `notion-create-pages`(신규 행) · `notion-update-page`를 **`insert_content`로만**(로그 append) · 읽기 전용 git 조회 |
| ❌ 할 수 없다 | `update_properties`·`replace_content`·`update_content`(**기존 행 덮어쓰기 전부** — 상태·담당·브랜치·우선순위·완료커밋) · 크리티컬 부여/강등((5)) · 사용자 결정 대행 · 파일 수정 · 재위임 |

속성 갱신은 에이전트가 출력의 `## 실행 필요(메인)`에 도구 인자로 넘기고 **메인 세션이 실행**한다. 클레임 직후 (3)-7 경합 재확인도 메인이 한다.

> 🔒 **이 경계는 도구 화이트리스트로는 강제되지 않는다.** `notion-update-page` 하나가 `insert_content`와 `update_properties`를 `command` 인자로 가르기 때문이다. 그래서 `PreToolUse` 훅(`Scripts/pm-board-guard.ps1`)이 `agent_type == "pm-board"`이고 `command != "insert_content"`일 때 `permissionDecision: "deny"`를 낸다. 훅 입력의 `agent_type`은 **서브에이전트 안에서 발화할 때만** 채워지므로 메인 세션의 정당한 갱신은 통과한다. 입력 파싱에 실패하면 `ask`.
>
> ⚠️ **훅 배선은 공유되지 않는다.** `.claude/settings.json`은 머신 로컬이라 **스크립트만 커밋되고 배선은 클론마다 수동**이다. 배선이 없는 클론에서는 위 경계가 **에이전트 정의의 규칙일 뿐 도구 강제가 아니다.** 새 클론에서 켜려면 `settings.json`의 `hooks.PreToolUse`에 matcher `mcp__.*__notion-update-page`로 `Scripts/pm-board-guard.ps1`을 물린다.

**드리프트 감사 (`/board 감사`)** — 보드는 stale해질 수 있고 git이 1차 진실이다. D1 유령 진행중(`담당` 공란) · D2 정체(`담당`의 MMDD 이후 그 작업 scope의 커밋이 없음) · D3 완료 미푸시(`완료커밋`이 원격 main에 없음) · D4 푸시 미마킹(원격 main의 커밋 scope에 대응하는 행이 완료가 아님) · D5 선행 해제 누락 · D6 크리티컬 미착수 · D7 경합(`주요경로` 공유)<!-- IF:MILESTONE --> · D8 마일스톤 미배정<!-- /IF:MILESTONE -->.
커밋 scope 관례: {{SCOPE_RULE}}. **git 저장소가 있어야 성립하므로 로컬 세션 전용이다.**

- ⚠️ **에이전트 정의 동기화 의무**: `.claude/agents/pm-board.md`·`.claude/commands/board.md`는 이 문서를 따르는 실행 주체다. **행 기입 의무를 늘리는 변경**을 하면 두 파일도 같은 커밋에서 갱신한다 — 안 하면 에이전트의 체크리스트가 신설 규칙의 반대를 지시하게 된다.

- 🔒 **조회 정책 — 일반 작업 세션은 마일스톤 DB를 조회하지 않는다.** 세션 시작 전수 조회 SQL((2))은 그대로이고, 마일스톤 DB는 **사용자가 지시했을 때만** 연다.
- **`마일스톤`**(relation) — 이 행이 속한 묶음. 듀얼 동기화라 마일스톤 쪽 `작업`은 자동으로 찬다.
- **마일스톤 × 우선순위 축 규칙**:
  - **마일스톤 = 언제(순서)** / **우선순위 = 그 마일스톤 *안*에서의 순서.**
  - **`크리티컬`만 마일스톤을 무시하는 인터럽트**다.
  - **마일스톤 미배정** = 아직 어느 묶음에 속하는지 정해지지 않은 것. `백로그` 우선순위와는 다른 축이다.
  - **완료·폐기 행에는 마일스톤을 소급 배정하지 않는다.**
  - 🔒 **개시 규칙**: **M(n) Exit 전에 M(n+1) 행을 착수하지 않는다.** 예외 3가지 = ①`크리티컬` ②현행 빌드를 깨는 회귀·크래시 ③**뒤 묶음의 판정을 오염시키는 결함**. 예외로 당겨 쓰면 **행 로그에 사유를 남긴다**.
- 신규 행을 만들 때((3)-3) `마일스톤`·`크기`도 함께 채운다. 어느 묶음인지 불분명하면 **비워 두고 사용자에게 보고**한다(임의 배정 금지 — 순서를 정하는 축이라 잘못 넣으면 착수 순서가 틀어진다).
- **마일스톤 DB `상태` 갱신 트리거**: 세션은 이 DB를 조회하지 않으므로 그냥 두면 배정 행이 전부 완료돼도 마일스톤은 영원히 `미착수`다 → (4) 마감 시 내 완료로 그 마일스톤의 활성 행이 0이 되면 사용자에게 보고한다(갱신은 사용자 몫).
