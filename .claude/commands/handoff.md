description: 세션 인계 준비 (컨텍스트 2/3쯤 호출) — PM 보드 행 갱신 + 코드만 커밋 + 재개 프롬프트
---

컨텍스트가 차서 새 세션으로 인계한다. 아래를 순서대로 수행하라.

1. **검증 확인 (멈춤 게이트)**: 미커밋 *코드*(`Source/`·`Scripts/`)가 있으면, **빌드+스모크가 통과한 상태인지 확인**한다. 미검증·실패 상태면 커밋하지 말고 사용자에게 알린 뒤 멈춘다(프로젝트 규칙: 검증 없이 커밋 금지).

2. **PM 보드 행 갱신** (`Docs/SSOT/Workflow.md` §6-9 "작업 후/중단 시"): 내가 클레임한 보드 행에 —
   ① 상태 유지(진행중) + **`담당` 비우고** 행 페이지에 재개 메모 append: 이 세션이 한 일(완료 커밋 1줄), **다음에 할 코드 작업(구체적, 파일/함수 단위)**, 블로커/주의, 미커밋 콘텐츠 목록(`git status --short`의 `Content/` 항목 = 사용자 작업으로 남김)
   ② `브랜치` 속성 = `git branch --show-current` 값 확인(트렁크 기반이라 평시 `main`, §6-7).

3. **코드/문서만 커밋**: `Source/`·`Scripts/`·`*.md`만 `git add` 후 커밋한다. **`Content/`(에셋·맵·BP)는 절대 커밋하지 말 것** — 사용자 콘텐츠 작업으로 남긴다. 커밋 메시지는 프로젝트 컨벤션(끝에 `Co-Authored-By: Claude ...`).

4. **재개 프롬프트 출력**: 새 세션에 그대로 붙여넣을 한 줄을 출력한다. **보드 행 URL을 포함**한다. 형식 예:
   `<유닛ID> 코드작업 이어서 진행 — 보드 행 <URL> 클레임(§6-9) + Game.md 먼저 보고, <다음 작업>부터. 콘텐츠/PIE 없이 코드만, 검증=빌드+스모크(+코어면 §6-6-1 레드팀 게이트).`

5. **푸시 여부 질문**: 다른 기기(핸드폰 등)에서 이어가려면 push 필요함을 알리고, 원하면 `git push origin main` 수행 여부를 묻는다.
   🔴 **단, 푸시는 §6-7 4단계를 통과한 뒤에만.** 트렁크 기반이라 푸시가 곧 머지다 — 미검증 커밋을 밀면 다른 세션이 그 위에 쌓는다. **코어 갈래(§6-5-2 T1~T5)인데 §6-6-1 레드팀 게이트를 아직 안 태웠으면 푸시하지 않는다**(인계 메모에 "게이트 미실행, 푸시 보류"를 남기고 로컬에 둔 채 넘긴다). 인계는 푸시의 사유가 아니다.

인자 `$ARGUMENTS` 가 있으면 인계 메모에 반영한다(예: 특정 다음 작업 지정).
